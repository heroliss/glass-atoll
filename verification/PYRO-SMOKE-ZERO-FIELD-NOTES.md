# Cold smoke / empty source generations

The first accepted field module (`55a47e8c…`) correctly cleared retired light, but keyed its cache on the emission ledger version. Fireworks publishes a new physical record generation even when no luminous source remains. Thus an enabled field plus cold smoke could submit the same zero MRT bake every physical frame, with another density-key change at20Hz. This was wasted work, not a retained-light colour bug.

The bounded fix (`eed47490…`) records when a **completed** bake wrote every texel, including padding, to zero. A zero-source request can then validate/repack the current physical packet metadata and publish the current snapshot/revision/source version while reusing that known-zero target. It does not upload textures or draw. Nonzero→zero always performs one complete zero write. Capacity growth beyond the old target, newly allocated resources and reenable initialize completely; shrinking inside known-zero capacity can reuse it. Relighting invalidates the zero flag and retirement clears again. The Gaussian formulas, bake shader, volume/host lighting, source ledger, physical covariance/mass and default-off path are unchanged.

Seven exact inverse edits restore the complete55a4 module. CPU control-flow checks pass7/7: under120 new empty-source generations and40 changed density snapshots the old factory submits122 draws, while the candidate submits only the initial lit and first zero draws. This is a stub submission witness, not GPU timing. The actual GPU zero helper passes20/20 in `pyro-smoke-zero-field-gpu-first.json`:60 empty generations and20 density updates leave bakes/version at2, update metadata, and all three RGBA32F attachments—including padding—read exactly zero. Expansion, same-object revision, reenable, relight and second retirement are checked. The prior independent numerical/volume fixture reran127/127 in `pyro-smoke-resolved-field-gpu-zero-regression.json`, with no shader or GL errors. Those reports remain separate from the original55a4 acceptance.

The actual resolved-light scene's32/32 gates establish the same physical event, source ledger, exposure/camera contract and cache behavior; they do not approve the radial flower shape. Isolated timer observations (.66ms60×120 and3.072ms4096×240) were one valid query each, not distributions or whole-scene FPS. Cold smoke still has physical density and can receive ambient/directional/lamps/torch; only retired pyro coefficients become zero. No age fade, mass removal, RNG or shader density noise was added.
