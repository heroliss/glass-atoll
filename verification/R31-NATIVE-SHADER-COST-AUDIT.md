# Native shader cost: source audit before the three-scope measurement

Read-only audit; no renderer, browser, context, production edit or GPU submission. The actual R31 receipt reports **59.307392 ms GPU**, 313.9 ms instrumented cold submission, 107 draws/41 render calls, 18 numerical stages, 10 blits, **4 mipmaps**, 16 clears and 10,441,410 geometry elements. The small R30 cold receipt's fifth mipmap is a different allocation state. None of these is steady-state FPS or a per-stage attribution.

## Existing measurement is enough for the next decision

`main.js` already has CPU `profileFrames`/`frameProfile` marks and a whole-frame `EXT_disjoint_timer_query_webgl2` timer. The CPU marks measure submission/JS/stalls; `aerial-perspective.js` explicitly reports `gpuMilliseconds:null`. Neither provides shader GPU timings. The R31 bridge already exposes sequential photometry, water and lens boundaries. One fixed fresh native frame with three nonoverlapping elapsed queries can attribute the existing workload without disabling objects or adding repeated benchmark scenes. The ordinary whole-frame query must remain excluded; elapsed queries cannot nest. Resolve all three only after submission, preserve non-disjoint/fault/state rules, and report scope sum versus the earlier independent cold frame without an A/B-speed claim.

- **Photometry** includes actual fresh shared SH plus forced cloud-shadow/indirect preparation; it is not exclusively CPU work.
- **Water** includes the submerged-prop auxiliary capture, opaque reflection, reflected transient-cloud delta, reflected volume and reflected SourceT/fireworks.
- **Lens** includes opaque main scene/water/sky, temporal, aerial integration/composite, thin-lens pass, main volume/SourceT/fireworks, bloom, SMAA and SDR output. A hot lens interval still would not isolate the water shader from sky/postprocessing.

## Concrete exact-work candidates, ordered after measured attribution

1. **Water's zero direct-key-light work.** The saved native receipt has `sunIrradianceStored===0`, sun-shadow disabled and zero submerged props. Nevertheless `water.js` fragment main computes solar Snell entry/Beer paths, three tree-shadow coordinate/derivative setups, cloud visibility and caustic sampling, and the full Beckmann direct-sun glint distribution before multiplying their radiance terms by zero. The PCF helper already avoids depth taps when disabled, so claiming 27 current shadow taps would be wrong. A uniform exact-zero direct-source branch could omit the remaining dead solar work while retaining all wave normals, reflected sky, local lights, ambient bed/volume transmission and foam. First constrain/prove the no-submerged-prop case: current `objectColour * solarTransmission` also depends on that path, even at night. Blindly moving it changes existing output. Uniform branching must preserve valid derivative evaluation and finite-domain behavior; verify day/night, nonzero moon/key, props, glint and local-light parity before promotion. Runtime uniforms do not prove the driver already eliminates this work.

2. **Shared shadow helper's disabled branch.** `sun-shadows.js:treeSunVisibility` builds projected coordinates and their derivatives before checking uniform `uSunShadowEnabled`. A uniform early disabled return can avoid this setup exactly without moving derivatives behind a varying frustum branch. This is smaller than removing all dead direct-solar work and may be redundant after candidate 1. It must retain the existing varying-branch derivative discipline when enabled.

3. **Aerial direct-source visibility.** `aerial-perspective.js:sourceAt` computes cached cloud/tree visibility before multiplying by `uSunRGB`. When all three stored direct-source channels are exactly zero, that visibility has zero contribution; diffuse sky and local sources still must be integrated. Keep extinction/T and altitude-dependent integration: black direct light does not make the air transparent. Its local loop already performs finite power/range checks. This is a restricted zero-contribution specialization, not a reduced step count.

4. **Volume zero-incident phase work.** The resolved smoke fragment uses four shared local lights plus SH1. It calls `localIncident`, then evaluates HG even when that call returned exactly zero due to its current range/cone/power rule. An exact-zero incident test can omit those phase evaluations; the same applies to inactive directional source phase. Preserve opacity and front-air T: dark smoke still attenuates background. The current combined proxy raster upper bound is 5,738,696 pixels across both eyes, so this is a meaningful candidate only if the water/lens intervals or a later narrow volume scope establish a hot volume path. Do not infer cost from that upper bound alone.

5. **Disabled-DOF arithmetic.** Actual DOF is false. `lens.js` still reads depth and evaluates CoC before multiplying radius by zero; its expensive 24-sample blur already does not run. A uniform DOF-disabled branch could omit the unused depth/CoC work and preserve vignette/color exactly. This saves work inside one pass, not that whole pass: actual vignette is enabled and finite effects are composited afterward. Moving vignette through bloom/effects is not an equivalent fusion.

The already-known deferred reflection-mipmap candidate remains separate: `water.js` composites opaque/cloud/volume/FW into one mipmapped target, while vendored r180 `render()` resolves MSAA and generates mips after each render. `r30-reflection-mipmap-enumeration.json` already records this. A final-only mip generation transaction needs proof that no intermediate consumer reads those mips and must retain the depth resolve needed before reflected volume. It is not a newly measured bottleneck here.

## Expensive paths that cannot be removed merely because the image is dark

`sky.js` performs atmospheric integration, conservative 32-probe cloud support and the configured cloud march. Occupied cloud cells use three self-shadow density samples; transient cloud lighting adds finite source/cloud/clean-air quadratures. The reflected opaque capture explicitly hides the ordinary sky, so do not count a second full ordinary sky draw there; the reflection has a separate transient delta. Global sky/cloud/star extinction and transient illumination survive a dark final SDR image. A heuristic night cut, fewer cloud steps or a lower-resolution sky is a model/quality change. A proof of exact source invisibility would be needed for a true zero branch.

The main lens target is four attachments (RGBA16F radiance, RGBA16F motion/coverage, R16F foliage depth, R8 reactive) at actual **8x MSAA**; reflection is native size at 2x. Temporal/aerial/bloom/SMAA/output still process native pixels. Lowering MSAA, reflection scale, smoke support or sample counts is not an exact optimization and is outside this audit. The threshold-free bloom intentionally spreads all radiance; final display blackness is not permission to bypass it.

Sand already contains footprint-aware micro-normal, grain/noise and photographed-albedo early exits; the refraction capture already restricts to layer 1 props instead of redrawing the expensive sand/forest. Cloud support and exact CPU sky-irradiance caching also already exist. Do not reintroduce these as new optimization claims. The ocean still has 410,881 vertices, and the main receipt reports 2,137,210 scene triangles/35 calls; sparse fireworks is not a sparse world workload.

The next action is the already-proposed single three-scope native measurement. Implement only a measured hot-path candidate afterward, with unchanged quality and separate CPU/GPU/image evidence. No broad profiler framework or engine migration is indicated by this audit.
