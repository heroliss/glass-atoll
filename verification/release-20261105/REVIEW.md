## 已修复

网站的 `scripts/vendor-glass-atoll.py` 为 `star-field.js` 添加无损 gzip 优先传输。旧代码只有 `.pack` HTTP 非成功时回退原始 `.bin`；请求被拒绝、解压构造失败或异步解码错误会直接使星空初始化失败，即使原始文件完整可用。

新加载器在压缩请求及完整解码阶段捕获失败，再尝试原始数据。成功解压不增加第二次请求，原始请求自身失败仍向上报告，避免把失败当作成功。压缩与原始资源都保留，所有图形数据、位数和内容不变。

`site/scripts/test-atoll-transfer.mjs` 直接抽取并执行发布快照中的实际加载器，使用原生 `Response` / `DecompressionStream` 和已知字节序列：7 组覆盖正常压缩、404、网络拒绝、损坏压缩、codec 构造拒绝、不支持解压、原始文件 503。全部通过。它是资源加载回归，不是实际设备或 GPU 验收。

## 独立引擎的后续边界

1. **全局物理时间。** `main.js` 仍将单帧物理增量截断为 55ms，低于约18 FPS时模拟会慢于墙钟。相同 `delta/time` 还被水体、漂浮物、天体、相机、烟花、声音事件及相关缓存共同消费。直接删去截断会跳过事件阶段或使差分积分不稳定；只对烟花改墙钟又会分裂场景时间。下一步应抽出统一模拟阶段，使用有上限的累计器/固定子步，同步处理暂停、隐藏页、诊断锁与恢复，最后再绘制。需覆盖同条件20/30/60Hz轨迹、事件不漏发、不重复、恢复不突进和主场景成本，不能在阶段发布前用一行替换冒称闭环。
2. **多发受光。** 当前 16 个地表代理与4个非烟花灯共用20记录预算，水面/空气另有聚合策略。压力场景中有限代理的空间误差仍超门槛，不能仅提高 CPU 工厂的最大数量而不改实际shader与共享预算。后续应在相同源、烟量与预算下改进分区/候选位置，在保留训练接收点之外的独立探针及实际GPU接收面验证，再比较完整CPU/GPU开销；不通过则保留当前版本。
3. **高分辨率密烟。** 11月1日高画质完整烟尘双发约22.59FPS；原约1FPS用户标签场景未同条件长期复测闭合。本轮没有新的整帧提速结论。
4. **主观声音与实景自然度。** 已有离线生产混音、波形、调度及媒体技术证据，不等同用户试听通过。未经真实听审不能替用户宣布音色自然度完成。
5. **初次资源。** 在线初次约54MB包含星表和银河HDR。该4K HDR已是Radiance RLE，追加gzip的离线试算为31,474,895→26,626,413字节，约15.4%节约；会增加实现、解码副本和回退复杂度，未在本轮加入。白天启动也等待夜空资源；安全按需加载需要让夜间切换等待完整资源、显示明确状态并处理失败/取消/销毁，不能先显示缺星或空白夜景。此项作为下一轮加载状态设计，不静默降低星表、纹理分辨率或删去夜景内容。

原始失败、候选与历史性能/音频数据均保留。网站阶段功能可发布，但这些独立物理和主观质量目标继续开放。
