# R31 原生画幅性能检查点

完整原生渲染链路已有实测证据，性能与视觉目标仍未完成。历史测量、当前代码和未测量优化分开记录。

## 两个历史测量版本

**原生完整帧**：main=`5b1541d2eddff1fa8a4c26eccd735657dac8b5a5e3c97a25001403cb1b1171f1`。`r31-native-scene-actual-gpu.json` 为 **6/6**；一次连续查询为 **59.307392ms GPU**，带验证插桩的 CPU 提交为313.9ms。它验证一个烟花事件在爆炸后+3.90s的实际生产场景：主视图、倒影均1209×1292；2,301个烟尘包、1,399个发光源、每眼1,402条透射射线；18次新光照计算，零 CPU 透射回退。读取6,248,112字节RGBA8 SDR图像。

**三阶段分析帧**：main=`bd51038a3018bbcfea92440f80e824673aa3c00c4711b94b7f8ee8ad0e6dadfa`，只增加受控分析入口。`r31-native-phase-profile-actual-gpu.json` 为 **失败4/5**：

|---|---:|---:|
| 光度与共享光场 |1.520640|27.4|

## R32待办与边界

- 先对夜间严格零贡献路径做依赖证明和小范围等价优化，再为**新源码版本**制定完整原生负载测量；保持画质、物质、光照含义和停止条件，不以降低采样或分辨率冒充等价优化。
- 复用既有因果生产构建与原生事务，在单发烟花较明亮阶段检查真实能量、受照烟云、地面/海面和构图。重新预规划实际源数与预算；保留+3.90s严格参照，不靠调高亮度/曝光美化验收，也不重建另一套渲染框架。
- 多事件每内核请求超过4m后的昂贵CPU回退仍未解决；已知双发负载可达到每眼约10.47m透射配对、共享光场约10.43m，合计约31.37m。不能把本轮单发覆盖推广为多发性能证明。

原生性能、明亮大烟花视觉、多事件回退及最终体验均待推进；本检查点不表示总目标达成。
