# 玻璃海：波、流与光的实现边界

检索日期：2026-10-26。此文记录物理依据和本项目的近似，不把参考论文的能力当成本项目已经实现的能力。数值结果以同目录的 JSON 验收报告为准；性能以浏览器实测为准。

## 为什么把长波、短波和水流分开

有限水深的线性重力波满足

\[
\omega^2=gk\tanh(kH),\quad c_p=\omega/k.
\]

当 \(kH\ll1\)，有 \(c_p\approx\sqrt{gH}\)，经典浅水方程可以描述长波传播；深水短波则有频散，不能让所有尺度都以同一个 \(\sqrt{gH}\) 速度移动。仅移动法线贴图没有解决水位、速度和海岸边界问题。[MIT 流体力学课程：有限水深频散](https://web.mit.edu/fluids-modules/www/potential_flows/LecturesHTML/lec19/node5.html)

本项目采用较轻的混合方式：有限差分的线性浅水长波负责局部扰动与岸边反射，35 个非公度方向的解析频谱负责细波，另设深度加权投影的稳定潮流场。组合高度为 \(\eta=\eta_{SWE}+\eta_{spectral}\)，法线来自同一高度场的梯度。几何、光学与焦散按各自采样间距低通，避免把无法采样的波频率变成格纹。

细波当前还加入表面张力项，使用 \(\omega^2=(gk+(\sigma/\rho)k^3)\tanh(kH)\)，其中 \(\sigma/\rho=0.000070244\,m^3/s^2\)、参考水深为 3 m；这是本项目的数值设定。长波求解器使用真实海床深度。35 个固定解析分量仍然不能替代局部波场的完整求解。

Jeschke / Wojtan 的 SIGGRAPH 2023 工作会在每个时间步重新分解 bulk flow 和 Airy surface flow，分别求解、输运并合并流量，还针对离散频散作校正。本项目**没有完整复现该算法**，也没有它的完整质量、动量交换和湿干边界能力；这里只采用分尺度处理的思路。[NVIDIA / ISTA 论文与原文](https://research.nvidia.com/labs/prl/shallow-water-simulation/)

## 水流必须能搬运物体

小扰动下，静态水深 \(H(x,z)\) 上的线性浅水模型为

\[
\partial_t\eta=-\nabla\cdot(H\mathbf u'),\qquad
\partial_t\mathbf u'=-g\nabla\eta-\gamma\mathbf u'.
\]

潮流 \(\mathbf U\) 与波速不是一回事。漂浮物应按 \(d\mathbf x/dt=\mathbf U+\mathbf u'\) 积分；不能直接按波峰的相速度 \(c_p\) 搬运。沿轨迹采样速度、用中点 / RK2 积分，可以观察漂浮物是否绕岛、避开陆地并随局部扰动运动。

具体到当前实现：叶片水平锚点由 **RK2 的稳态投影潮流 + 二阶深水 Stokes 漂移** 推进；零均值的波浪轨道位移只叠加到显示位置，避免与 Stokes 漂移重复计算。叶片高度取共享的细波 + SWE 水面。CPU 叶片轨迹**没有读取 GPU 中局部浅水扰动的水平速度**，因此不能声称完整的拉格朗日波流耦合。细波使用累计流动偏移而不是简单的“当前速度 × 总时间”，所以调整潮流不会瞬间跳相。

在水深变化的静态背景上，连续性要求 \(\nabla\cdot(H\mathbf U)=0\)。若 \(\mathbf U=\mathbf U^*-\nabla\phi\)，应解

\[
\nabla\cdot(H\nabla\phi)=\nabla\cdot(H\mathbf U^*).
\]

陆地边界采用零法向通量；外边界的入流 / 出流必须明确。普通 \(\nabla\cdot\mathbf U=0\) 投影不能自动保证变水深下的水量连续性。压力投影与沿速度场输运的基本机制可参照 Harris 的 GPU Gems 第 38 章；该章的完整二维不可压 Navier–Stokes 求解器不等于本项目的稳态潮流投影。[NVIDIA GPU Gems：GPU 流体模拟](https://developer.nvidia.com/gpugems/gpugems/part-vi-beyond-triangles/chapter-38-fast-fluid-dynamics-simulation-gpu)

## 性能与验收约束

- 显式二维长波步长应满足 \(\Delta t\,\sqrt{gH_{max}}\sqrt{\Delta x^{-2}+\Delta z^{-2}}\le1\)，并留余量。后台停顿后使用有限子步，不能把数秒钟一次性灌入积分器。
- 速度放在单元面、水位放在中心，使用同一面通量的差分，可让封闭边界的总水量变化相互抵消。静水 \(\eta=0,\mathbf u'=0\) 在不平海床上应保持静止。
- 投石应注入局部动量，或使用离散积分为零的水位扰动。靠岸裁掉一半高斯环后，必须重新校正湿单元上的净体积；否则每次投石都在凭空加水。
- 需要分别记录静水误差、总量误差、最大 CFL、干岸穿透、投石后能量变化和漂浮物位移。一次画面好看不能替代这些检查。
- 压力投影迭代应检查残差，而不只数循环次数。平流的数值稳定不等于精确；大步长仍会丢失涡旋、细节或穿越边界。
- 焦散网格、海床纹理和屏幕像素各有 Nyquist 上限；增加光学微波后，不能继续用低分辨率顶点网格投影全部频率。

当前方案仍是高度场与小振幅近似：没有翻卷浪、真实破碎、水体多层交叠、三维湍流、完整波流双向耦合或精确 Stokes 漂移。SWE 长波不能冒充厘米短波；解析细波也不能冒充求解出来的局部水流。浅水、风浪、流动与光学的参数必须保持同一米 / 秒尺度。

## 已留存的数值验收

- `optics-math-check.json`：27 项通过，包括实际 GLSL 的 Fresnel、Snell、Beer、重力毛细频散、累计流动偏移、多画质梯度和焦散通量。解析梯度检查仅覆盖细波部分，明确不包括 GPU 采样的 SWE 纹理。
- `hydro-math-check.json`：38 项通过，直接调用实际 CPU 求解器与冲击构造函数；覆盖平底、斜底、岛屿、封闭水池、当前沙洲和全干区域，独立测量深度通量散度与湿岸冲击体积。
- `hydro-gpu-check.json`：由浏览器运行隔离的实际 Float32 渲染目标检查。验证 2 m 平底中的真实湿单元数与深度通道，再测静水、投石后能量、早期体积、干岸运动和渲染状态恢复；报告本身记录通过 / 失败，不能用 CPU 验收代替它。

CPU 潮流在较粗网格投影后插值给 GPU；插值并非在细网格上重新求得严格零散度。SWE 的外圈海绵和上游驱动会交换体积 / 能量，晚期全域体积不应被误报为封闭系统守恒。检查 GPU 状态时还必须核对湿单元和静态深度，防止“渲染失败、读回全零”被误当成完美静水。
