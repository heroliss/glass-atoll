# 近看烟花时的半浮点天空色带：只读诊断

生产源预算已按实际 GPU 证据做最小修复：只在32×32网格累加前排除确定处于同质深度裁剪外的源。源渲染、公开的单源 Gaussian 公式、边界 fallback、网格与安全系数不变。修复后实际 GPU 回归及近景色带复核已完成，见末节。

## 已重现的原因

原始证据为 [四组核形实景报告](pyro-smoke-kernel-scene-first.json) 的 `detail / point20`：1209×1292、seed42、ring、强度16、爆后1.1秒，相机位于 `[4.2906,84.3273,-23.7901]`。该次烟花原始预算为 **35947.70485573332**，存储曝光 P 为 **−1.25EV**，摄影曝光 C 为16.5EV；实际反射 RGB 全零。天空 opaque 的存储最大值仅约1.6153e−5，进入半浮点次正规数区间。截图确实存在明显色带，不以数值检查替代视觉判断。

[CPU 重现](fireworks/near-plane-cpu-repro.json) 使用当前同一生产工厂与实际 seed/时刻；所有 ring 根星具有相同出生时刻和阻力，实际风造成共同平移。以记录中的光源质心校准该共同平移后：

| 景别 | 原报告预算 | CPU 重现 |
| --- | ---: | ---: |
| 正面 | 2.0284301915312732 | 2.0284301915312737 |
| 斜侧 | 6.588153724515206 | 6.588153724515206 |
| 近看，镜像路径 | 35947.70485573332 | 35947.70485571808 |

近看镜像中只有一个源触发旧版整屏 fallback：中心 `w≈0.1172346 < near0.15`，所以 CPU 将其巨大的离轴 Gaussian 峰值计入整个32×32网格。然而镜像相机使用斜截平面，实际同质坐标 `z≈960.848`、`w≈0.11723`；它远在 `z≤w` 裁剪范围外。真实烟花顶点只扩张 xy，四角 z/w 均为同一中心值，扩大的四边形不能改变这个深度裁剪结果。

旧算法只检查 w 正值及矩形/近面，不检查真正的同质 z/w。这会让硬件不可能画出的源压低全场 P，造成数值精度损失。这里不需要加亮材质、调整源强或提高摄影曝光。

## 实际 GPU 证据与有界修复

[实际 GPU 初次报告](fireworks/near-plane-scene-first.json) **8/8**：实际镜像 body97 的 `w=0.1172305559±5.28e−5`、`z=960.84778±0.000454`，全屏保守代理的硬件覆盖为 **0**；入场/结束 GL 错误均0。该源旧峰29956.277816乘1.2后形成约35947.53的虚假预算。这是真实上下文、实际镜像矩阵与实际源数据，独立于 CPU 重现。

仅排除可证明完全位于同质深度裁剪外的源，不做中心 xy 剔除，不改光点核、投影端点、网格、边距或1.2安全系数。

候选以实际上传的 Float32 中心与 Float32 `(projection×view)` 矩阵计算 z/w；四项点积误差使用 `γ7 Σ|aᵢbᵢ|`，再留次正规数冲洗余量。只有 w 上界不超过实际 Float32 `0.01`，或 z/w 的误差区间仍严格位于近/远裁剪范围外，才允许排除；边界不确定时保留旧预算。

修复在该次历史 CPU 重现中保持主相机近看预算 **7.18615290875** 不变，仅将镜像预算降到未改的旧烟雾项约 **0.00047151**。另将实际 GPU 初次报告的源行输入修复前/后同一工厂：主源预算逐位保持 **7.18568135610271**，镜像源预算 **35947.533379485154→0**。后者只输入报告里的发光源行，因此不包含另存的旧 smoke 记录；真实场景仍保留原 smoke 预算，不能把这两个数值组混为同一完整场景。

GPU 入口：[near-plane-scene-check.js](fireworks/near-plane-scene-check.js)，`runNearPlaneBoundSceneCheck(THREE,renderer,{fireworks,camera,water,optics,frame,expectDepthClip:true})`。它取实际主/镜像矩阵和源行，用覆盖全屏、保留该源同一 z/w 的保守代理作硬件裁剪证据，同时测试裁剪边界的不确定带及恢复调用者 renderer 状态。默认验证修复后生产预算逐位等于独立原始源行的区间裁剪重建；`expectDepthClip:false` 可验证冻结的旧实现。无覆盖证明该 z/w 的任意真实 xy 四边形也无法通过深度裁剪；它不是新的粒子光度渲染器。

## 修复后实际验收
