# R34：三芯体量、当前构图与logical-all烟源的独立定量笔记

这是只读源码/CPU分析，没有浏览器、renderer/context/GPU、host重放或生产修改。数值不是物理测量，不是新shader/性能准入；R33封存与现有19m/s旧契约不动。

## 体量差距确实存在，不能只归因于机位

[原引用厂商页面](https://ojiyaenka.base.shop/items/34029650)当前仍写四号玉示例为160m高、120m直径；它是厂商的产品尺度说明，未给展开时刻、光强曲线或测量误差，不能推出所有120mm烟花同宽，亦不能把120m指定为爆后+.70的直径。

`r34-three-layer-width-independent-study.{mjs,json}`调用当前纯`createFireworkEvent`和实际burn采样函数，重建本次seed341070及实际回执方向/原点/旋转。192体/64每层、峰值总预算1421.292953…和最大寿命4.870042…与回执精确相符。Node绝对burstTime比浏览器多1ULP(7.105e-15s)，已保留首次fixture停止源码并显式记录，不声称完整跨引擎物理相等。下表是相对共同平移的燃烧头几何：所有根同birth/drag/gravity，均匀风、共同burst速度和重力在两两距离中相消。

关键是外蓝模板只有3.4秒（±6%），不是native定义的4.3秒。三层速度倍率是1/.7/.4；native初始speed实际是13..19，19仅为上限。对当前k=9.81/16=.613125，径向位移`r=v0*(1-exp(-k*t))/k`。因此，即使假设全方向正好19m/s且燃到外层允许最长3.604s，直径绝对上界也只有55.177m；中/内层对应41.202/20.216m。尾迹短暂延长光学支持，报告没有把它错误等同燃烧头宽度；它不可能合理解释120m参考与约52m主体间的巨大差距。

源码同时明确`widthCalibrated:false`；高度标定只针对参考80°上升160m，本次实际71.51°升高149.68m。旧intrinsic19硬门是兼容/回归合同，不是自然界普遍的星体初速。已经“高度参考已接线，宽度未标定”，这是真实scope gap。

## 新版本宽度校准路线（尚不实施）

1. 新建例如`three-heart-scale120-v1`的独立版本或`widthProfile`，保留three-heart-v1/legacy全部字节和旧19门，不把旧fixture改成更宽后宣称回归一致。选定一个厂商/视频的目标宽度范围及其展开时间，而非全口径通用120m；显式记录静态图片快门/透视/距离的不确定性。
2. 先保留192头、原色/寿命、RNG命名空间和强度1，单独拟合“初始径向速度→在明确发光阈值/时刻的外层直径”。现模型若只求本次全寿命上界120，倍率约2.309；若求≥10%源门最大120，约2.349。它们只是代数起点，不是批准参数。保持同k，理想对称头在2.5/3.0/3.4秒达到120m所需水平分量分别46.918/43.738/42.012m/s，证明旧19不够；真实有限64方向/速度分布还需独立拟合。
3. 速度扩张相对burst COM做，保持参考发射/apex时刻和COM惯性，不凭空给COM向上推力来救画面。球形烟花本来有上下/斜向分量，不能为避免下落把全部头强制放到横平面。当前16m/s匹配的线性阻力只是显示近似；未来更换二次阻力/尺寸质量模型应另版本、多点轨迹拟合，不能只用一个终端速度同时声称高初速减速也物理精确。
4. 全寿命世界高度/接触和尾迹快门支撑重新解析包围：新速度和最大寿命共同决定最低燃烧头/尾迹高度，不只看爆心151m。检查低角度允许域、发射散布、COM下沉、wind history、burnout后脱离余烬和接触退役。保持已有地面/水面支持合同；若目标组合不满足高度裕度，应明确拒绝/调整该版本允许域，不能让光点悄悄穿地。
5. 更新该新版本的limits、show envelope、getBounds、autoFrame/director预报、qdot与曲率pad、近面/水面/反射支撑、source T原始射线与量化域。有限火点扩大2.3倍会改变屏幕重叠、光学核和烟源空间，不是只改UI范围。192body身份可以保持，但不得因为投影大就暗中删点/减少尾迹bin。
6. 光度与几何分开标定。相同总参考cd铺到约5.3倍面积，图像平均亮度可能更低；不能静默再乘面积补亮。总光通量/每头光强、燃烧颜色/亮度时间曲线与摄影曝光需要独立证据。当前moment cluster必须重新求中心/协方差、半径与全局受光bound；SH全源、云/空气/地表/海面与间接反射都要用同一版本。主爆音效已获认可，不随视觉尺度自动加响。
7. 烟量总预算、ID和时间保持；速度扩大使past-segment covariance和烟团投影/遮挡范围变化，重验all-body scheduler和full Gaussian source T/SH；配对数可能不变，像素overdraw、条件数、receiver近源峰值和云覆盖成本仍可增加。先新的CPU完整因果数据和小实际核门，再一个明确预算的实景观察，禁止只以包数未变声称性能免费。

## 当前固定近景能改进，但不能把20m花变120m花

当前相机[-133.92069,12,-315.65657]距+.70发光中心约479.84m，实际垂直FOV65.47045°（28mm/36mm传感器高），CPU头支持投影约48px；与截图约40px相符。focusMetres411m在DOF=false时不会导致模糊。`getBounds()`预报整根寿命、火箭/地面、8m pad与9.8s风漂烟范围；`frameFireworks()`再拟合其AABB全部角点+虚像，包含实际没有光源的“近地前侧上空角点”。它是保守全程构图，当前相位会留很多空白。

对同一暂停+.70的单次近景可用`setCamera([-52,12,-177],[73.3,0,94.83])`。按实际cluster maxExtent10.78765+1m pad、岛体[-39..44]×[0..18]×[-27..30]和均值水面虚像CPU投影，最大|NDC|分别：火花.898、虚像.865、岛.645；主体约75px，改善约1.57倍，仍不是照片验收或新GPU预算承诺。截图可临时隐藏右侧UI避免挡岛，记录并还原界面。

+.70爆心149m且直径仅21m，要求岛、整花与整虚像同框时，几何比例本来就把花限制在约80–90px；用更近相机/更长焦无法同时无裁切变成300px。这个固定机位不适用于后来+1.70已扩张的20m半径，后者应重新按实际cluster/包络计算。背景近黑还与太阳−52.20°、月亮−44.57°及当前cameraEV14有关；几何诊断不能冒充曝光根因结论，交由独立光度审查。

## logical-all单枚+.70：覆盖更完整，但不是“更多包必然更浓”

已有`setSmokeReviewProfile('logical-all')`是明确QA-only host替换，保持trajectory-v1 / past-segment-v2 / Brownian / centralFraction.20；必须先空场景0active/queued/packet才能调用，不能在当前24P或活跃事件上替换。不需新求解器、容差或默认推广，reload恢复原生产host。

源码bodyId首cell年龄在.1010049644–.2993788189，后续步长.30；本次192根寿命均大于2.4s。+.70每根恰有2个完成cell，第三最早.7010049644尚未到；加9lift+3burst，共396个Gaussian生成上界，低于4096且没有容量合并需求。实际固定步长提交时间仍应记录，不用目标time冒充每包已提交时刻。

若同相位仍1728个SH源与各眼1728条光路，T每眼/SH分别684288pair，合计2052864；当前精确矩形planner各2map+reduce，9数值draw。仅说明小于生产4m每请求政策，不保证整帧/体积overdraw/FPS。实际几何source计数和fallback必须再看receipt。

本次lifetimes的均匀life源到第二cell完成时仅释放约6.7384的author参考面积，总预算20.35，约13.6116仍保留；它不是kg测量。原two-births在+.65已将约20.35铺到24代表包。logical-all更多、更细、沿所有192路径分布，但+.70总烟量反而更少，视觉上未必更浓/更亮；若结果不符真实烟量，应单独标定物质/消光/光度，不把提高packet数当根因修复。
