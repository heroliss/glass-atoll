# R37：撤回负收益缓存，定位首次光学构建

整体目标继续active，照片感和性能目标尚未通过。本轮没有合入提速或图像算法变更；新增的生产代码只是在现有`profileFrames`采样期间记录CPU光度子段。

## 实际决定

实际工厂探针发现代表性两眼工况的逐源投影重复2816/3072/3052次。候选用完整相机/光学/行输入签名保存结果，后续尾迹采样复用；精确性6/6通过，但216条fresh-generation CPU ABBA样本中，开启后平均慢26.8%、中位数慢29.3%，三个阶段均变慢。该测量没有真实GL/render/SourceT，镜眼也没有water的oblique投影，不能冒称原生GPU结果；这个负收益已足以停止准入。

候选、输入、依赖与全部结果保存在`baselines/r37-rejected-source-projection-reuse/`。正式`fireworks.js`逐字节恢复R36的`03fdb703…c735`，对应main QA开关也已撤掉。未执行原拟缓存原生A/B，不将“缓存命中多”当成收益。独立存量审计4/4核对原始样本与回退身份。

## 真实运行发现

随后对原生1209×1292、中档实际采样、HDR、普通24团代表烟的一枚长金尾正常演化采样约3秒。91条CPU光度记录：

| CPU wall/submission子段 | 均值 |
|---|---:|
| 主视图光源上界准备 | 8.333ms |
| 烟尘受光准备 | 2.497ms |
| 镜像光源上界准备 | 0.800ms |
| 间接光/云影 | 0.695ms |
| 光源簇 | 0.316ms |
| 整个光度准备 | 12.973ms |

主视图通常是新generation的首次`opticalRows`消费者，承担接触支持、锚点、八段快门RGB和新记录构造；镜像随后通常命中已有光学行，再做自己的投影与上界累计。这个源码关系与差值相符，尚未把8.333ms细分到RGB积分、运动或分配/GC，不能全归因于某个函数或宣称都可省掉。

这段实际演化约30.01FPS、GPU均值22.42ms；它是基线诊断，没有候选A/B。全部异常值保留，早期CPU大帧的主场景/镜头段约142.5ms，GPU样本异步，不能按数组下标与CPU大帧对齐归因。91条细分记录与窗口外边界帧合计新增92次SH刷新、184次T准备，未用暂停缓存冒充演化性能。端点烟团均24，SourceT/SH均GPU有效，无CPU遮光查询/GL错误。

墙钟3.032秒、物理推进2.8907秒，55ms时钟限制的问题仍存在。它没有在本轮与光度改动同时调整。
