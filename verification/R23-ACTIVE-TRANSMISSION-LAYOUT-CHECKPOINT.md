# R23：烟尘遮光的有效布局已默认启用；密烟性能继续进行

2026-10-29。整体目标仍 **active**。这轮只改变烟尘遮光数值缓冲的布局与有效绘制范围，不改变烟量、寿命、燃烧点、光强、RGB、轨迹或画面配方。蜂群仍在显式验证入口，未推广到日常样式菜单；主爆音效保留。

## 已落地

新增 `smoke-transmission-layout.js`，用实际光线数量排列每个64烟包的光学厚度小计，保留原有包顺序、分块求和和最后一次指数变换。构造容量仍为18000条源光线、4096烟包、每次请求1048576配对。中间目标由构造最大矩形改成该预算内的保守容量包络；常规请求只绘制实际前缀。零光线或零烟包时仍生成整张中性透射结果，避免旧内容残留。

`pyro-smoke-transmission-gpu.js` 默认 `active-count`。同一原生容量的数值GPU缓冲由19,849,216字节降为1,970,176字节，减少约90.1%；这不是整个网页显存占用下降90%。非空结果只有 metadata.count 行可读，未使用的容量不是有效结果。每个请求完成后才发布新版本；失败时退役旧结果。QA接口支持显式旧布局对照，并阻止冻结测速中修改路由、容量或布局。QA阶段失败返回及抛异常均清除对应准入凭据。
