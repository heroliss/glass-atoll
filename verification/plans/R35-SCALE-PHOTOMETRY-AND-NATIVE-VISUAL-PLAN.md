# R35：把烟花尺度、发光过程与完整产烟放在同一版本校准

R34已完成两枚正常单发观察：三层颜色/尾迹可见，但普通烟源仍只有24包；连续逻辑源在+.70为396包，+.1.70为1051包。后一阶段暴露并修复QA宿主切换丢失ellipsoid/tiled64的问题。同阶段恢复受光时完整物理快照不变；这不等于数值场重新做了独立像素oracle或整帧性能通过。

当前图像仍未达到照片感。下一轮优先处理实景发现的尺度与光度缺口，云密度精确2候选保持未推广，不能让微优化替代视觉目标。

1. **独立尺度版本，保留旧契约。** 本次192点三芯的外层+.70直径20.824m、+.1.70为38.631m，整个发光寿命最大51.963m；旧19m/s与寿命上界无法达到所引用120mm示例的120m直径。建立明确的新版本，而非改写旧测试基准。供应商只提供160m高度/120m宽度示例，没有展开时间和光度曲线；校准的是一个有说明的参考包络，不能说所有该口径都遵守同一数值。
2. **先选清楚宽度的定义。** 用水平燃烧主体或发光支持，区别于全路径、烟包、尾迹、RMS半径、最大单点与分位外轮廓。记录选定时间与可见性门的作者选择，不冒充供应商测量。由实际解析轨迹求初始冲量；保留方向/速度随机性与分层比例，COM仍在apex附近爆开，不增加虚假上推。线性阻力/终端速度近似、接触/海面支撑及全寿命亮点高度一并检查。
3. **同源更新全部依赖。** 新速度/寿命必须贯通CPU运动、GPU头/尾/快门支持、未来包围与镜面、相机自动构图、连续烟源位置与协方差、SH/光源空间矩、光账本和安全存储界。保留192主体及既有物质量账本；更多烟包不代表更多烟量，也不能减掉暗烟来过性能门。
4. **分开发光阶段与绝对标定。** 当前5–10参考cd/星、三层总峰预算1421.29并非实物测光，+.70仍有约89.8%预算，远地/高云本来很暗。没有发现曝光P重复衰减；不能用普通视频或官方某类flash超过30000cd的叙述，直接推导这枚持续火星的乘数。研究独立的短时burst-flash基础发光点与持续星体包络，时程/光度若采用作者近似必须明确标注，不能只抬全局曝光或假称真实SI校准。
5. **一致的受光与呈现。** 审查地表local光280m截断与cloud/SH无同一截断的差异；近源半径是正则化，不是光传播终点。让核心闪光、星体、尾迹都走同一RGB/线性空间/P/C/显示链及当前来源账本，检查地面、烟、云、大气和水面反射。HDR与SDR分别检查；当前屏幕系统报告1270nit不等于场景绝对亮度标定，不能直接把系统峰值当光源亮度。
6. **先单发后多发，明确验收范围。** 新版本先有意义的运动/光账本/包围CPU检查与最小真实GPU比较，再完整原生明亮画面和连续表现。保留生产4m请求/1m每map/8map边界，另审多发完整请求，不能凭一发1051包恢复受光就宣称任意积烟60FPS。普通运行GPU读数与固定100ms门分开；旧不匹配pins的helper继续拒绝，不用改旧pin冒充新验收。
