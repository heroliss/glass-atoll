# R29 later-lifetime calibration runner

This is a verification-only calibration of the actual later native workload, following the admitted R27 SourceT and R28 complete SH1 paths. Root alone executes GPU work. It is not another candidate/production duplication: first prove the capacity-only 1.4m→4m policy delta and unchanged kernels, then calibrate the deployed production factories directly on three immutable original native phases.

## Files and immutable jobs

- `r29-native-calibration-runtime.js`: common supported-native-state guard, descriptor interception, fixed-field preparation, job timer, readback and both unchanged numerical acceptance tests.
- `r29-source-peak-gpu-check.js`: `runR29SourcePeakGPUCheck`, revision `r29-source-peak-v1`, statically imports the actual dense60Hz SourceT peak.
- `r29-light-peak-gpu-check.js`: `runR29LightPeakGPUCheck`, revision `r29-light-peak-v1`, statically imports the actual dense60Hz SH peak.
- `r29-joint-peak-gpu-check.js`: `runR29JointPeakGPUCheck`, revision `r29-joint-peak-v1`, statically imports the actual dense60Hz combined peak.
- Motion owns `r29-native-phase-{source-peak,joint-peak,light-peak}.js` with exports `R29_NATIVE_PHASE_FIXTURE`, `R29_NATIVE_PHASE_FIXTURE_DIGEST` and `r29CanonicalJSON`, full original sources/ledger/rays/packed words and independent offline references.

The thin wrappers select a compile-time fixed job, never caller-provided counts, data, caps, camera, source filtering or oracle. The common runtime pins the wrapper/artifact/canonical identity and current production source/cached functions before context access. Root injects trusted production factories after the options spread. Unknown options reject before context or constructor. The helper creates no renderer/context/canvas and draws no scene, volume or reference GPU result.

All original native objects, full padded upload words and complete independent offline references are privately owned before the first await. A declared payload reservation is checked before cloning; it is not a JavaScript heap or driver allocation claim. For the joint job the top committed snapshot is decoded exactly once, as is its emission ledger; both kernel inputs refer to the same owned snapshot generation and current-time source association. SourceT still uses its own original view rays and sorted optical rows. Main/reflection attenuation is not reused across views, and optical rows are not substituted for the SH emission ledger.

## Fixed resource and work policies

SourceT uses capacities 18,000/4,096 with legacy `maxPairs=1,048,576`; SH uses 14,000/4,096 with legacy `maxBakePairs=1,048,576`. Both daily constructors explicitly use complete request 4,000,000, per-map 1,000,000 conservative64 slots and eight allowed maps. The old defaults and existing positive-safe-integer SH legacy API remain unchanged. No optical math, inner64 accumulation, increasing reduction, shader, native guard, unit, particle mass, lifetime or source ordering changes with this policy extension.

Each fixed wrapper independently verifies the final frozen native count and exact rectangle plan. Expected actual job limits are SourceT peak four maps + reduction (five draws), SH peak five maps + full MRT3 reduction (six draws), and same-generation joint SourceT three maps + reduction plus SH five maps + reduction (ten draws). Final immutable data determines the exact read caps: all valid SourceT RGBA rows and all valid SH packet rows on three RGBA attachments, plus at most eight partial cells for each selected kernel. The global allocated final SH zero suffix remains a full-viewport/pinned shader/CPU contract; SourceT only promises the valid metadata count extent.

## Submission and failure contract

One owned timer encloses the complete fixed job, including both synchronous prepares in the joint case. Its 25ms gate is retrospective; it cannot interrupt already submitted maps. GL errors, incomplete FBOs, unlinked programs, context loss/replacement or instrumentation violations stop before the next numerical draw. There is exactly one uninstanced numerical triangle draw per render, no clear, no VTF or reference/scene draw. The timer must be available, non-disjoint and ≤25ms before any numerical readback. A failed submitted job preserves an unavailable/failed timer receipt and releases all instrumentation and owned resources.

Each prepare retains its normal synchronous complete-publication contract. Its owned texture is unavailable during all maps and the reduction; generation metadata must match on completion. The joint helper does not lend either texture to a live application consumer. It restores the supported Three state, distinct READ/DRAW framebuffer and draw-buffer selections, PACK/UNPACK settings and PBOs, COPY_READ, descriptor ownership and renderer flags before yielding. Private program/VAO cache identity is not part of the contract. No stale or partial input generation is an allowed substitute for current results.

## Numerical acceptance and next boundary

All SourceT rows retain the existing physical-reference 1e-5 and quantized-double 8e-6 absolute bounds, [0,1] RGB range, alpha1 and exact T1 for inactive/zero-length rows. The finite-SPD Gaussian extinction, original-double endpoints and per-source ray normalization remain unchanged. Sampled partial tau is finite and nonnegative with alpha0.

All SH rows retain the .002 per-packet-peak-reference-C0 normalization for C0 and C1 vector error, nonnegative angular reconstruction and independently checked global/per-packet source-group bounds. Signed fourth channels remain C1z, not opacity. The original trace-isotropic Gaussian-emitter SH1 surrogate is not promoted to full anisotropic/self-shadowed radiative transport by the larger budget.

The three complete jobs calibrate the known later single-firework cliffs without dropping matter or sources. They still do not establish complete evolving-frame cost. After the numerical/calibration evidence, the next step is one coherent fresh normal frame at the same generation, including actual consumers and their separate main/reflection/SH costs. Multi-firework accumulated smoke, normal motion, whole-frame FPS and final visual acceptance remain subsequent measured work; isolated kernel timing is not a 60FPS claim.

The exact fixed read caps are 21,984 /122,832 /110,832 bytes. Old +2.70/+3.85/+3.90 raw captures remain historical inputs and are not the primary calibration workloads.
