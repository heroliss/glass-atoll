# R26 synchronous complete SourceT candidate

This work implements a **verification-only** synchronous candidate in [r26-complete-transmission-candidate.js](../r26-complete-transmission-candidate.js), copied pack/layout policy seams, and an independently owned pure rectangle planner. `main.js` imports the candidate only for explicitly locked QA entry points; the live field still uses the incumbent factory. No browser/GPU call was made by this child workstream. [Own CPU result](../r26-complete-transmission-candidate-check.json):9/9.

`createCompleteTransmissionCandidate(THREE,renderer,{maxSources=64,maxPackets=48,maxRequestPairs=3072,maxMapPairs=1048576,maxMapDraws=8,layoutMode='active-count'})` separates the complete logical request allowance from conservative per-map64-slot work. The verification-only complete request ceiling is1,400,000; each map is at most1,048,576 conservative slots and map-draw count is explicit (1..64, default8). Invalid policies reject before GL; unsupported counts/request/map schedules withdraw public output without drawing. The incumbent defaults64x48/3072 remain. These candidate policy names intentionally differ from the old `maxPairs` constructor argument; the live caller has not been migrated.

The packer copy changes only the explicit request policy seam. Original full-SPD, mass/extinction, reflected original-double rays, Float32 conditioning and quantization checks remain. The CPU source comparison normalizes line endings and the reviewed policy identifier before checking the physical pack-body text. There is no runtime source rewrite, packet slicing, per-map input upload, particle/source omission or altered finite-column shader. Original64-packet inner sums and increasing-tile reduction followed by one exponential are unchanged. Expanded shaders, full padded upload bytes and every valid synthetic final row match the actual production factory across eleven old-domain fixtures, including0/1/63/64/65/255/256/257/513 rows and a1740x500 case.

Each synchronous `prepare` packs once, preflights the complete map schedule, submits exact nonoverlapping global-index rectangles into one private partial target, and performs **one** final reduction. During every map/reduction the public texture getter remains null. It becomes effective only after the entire loop succeeds; every FBO/link/GL/context/render fault withdraws it. Retrying after a recoverable render fault redoes the complete generation. Empty requests retain one newly drawn full allocatedT1 output; nonempty shrinking requests keep the existing `metadata.count` valid-read contract, so capacity suffixes may be stale and must not be read. Borrowed T must still be consumed immediately for the matching source/density versions.

The preserve guard now includes the established supported-Three READ/DRAW/viewport/scissor/XR/shadow/clear/tone state plus PACK/UNPACK/PBO/COPY_READ. Before first typed-array uploads it nulls the unpack buffer and neutralizes all row/image/skip/flip/PMA/conversion state; all saved state is restored after the synchronous job. This is a named binding contract, not a claim about undocumented program/VAO cache identity. Every submitted map and reduction checks FBO completeness and linked program, rather than caching away later map checks. GPU timing and preemption are not implemented in this candidate: a synchronous job queues its maps without awaiting per-pass timers. Root requires a separate controlled GPU gate before any larger dispatch or production promotion.

The1734-source755-packet CPU factory fixture contains all1,309,170 logical pairs. Exact map cells total20,808, equivalent to1,331,712 conservative64slots. With per-map cap1,000,000 the planner emits three maps and one reduction; no partial cell is duplicated/dropped. Fixed numeric GPU allocation is499,712B and CPU upload buffers135,168B for these constructor caps. The old1,048,576 whole-request pack policy still rejects this input, as expected. This fixture proves the larger-policy routing only; it is not native optical/hardware or speed evidence.

The compact allocation bound is unchanged algebraically. For explicit1.4m and maxSources18000/maxPackets4096 it allocates39,875 logical partial cells, rounded to39,936; the CPU test checks all4096 packet counts at their maximal feasible active count. All policies and conservative padded work are reported. A logical1.4m request envelope is not a total-frame budget: main view, mirror and resolved smoke lighting remain independent consumers, and the resolved-lightfield cliff remains outside this SourceT change. This candidate does not silently fix that path, admit native throughput, or establish60fps. A larger calibrated total workload remains possible through bounded measurements;1m is not a permanent user constraint.

First test iteration caught two fixture issues: CRLF-vs-LF text comparison and a neutral/shrink test that accidentally requested65x65 under the default3072 cap; its report is retained at [initial CPU check failure](../r26-complete-transmission-candidate-first-check-failure.json). The corrected text audit explicitly normalizes line endings and the shrink fixture uses16x65. Neither failure required changing the physical math.
