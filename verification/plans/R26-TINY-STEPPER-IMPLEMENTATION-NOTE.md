# R26 fixed exact SourceT stepper implementation

Implemented only [r26-tiny-transmission-stepper.js](../r26-tiny-transmission-stepper.js), with [CPU checks](../r26-tiny-transmission-stepper-check.json). No production module, browser, renderer context or GPU was changed/executed by this workstream. The current production SourceT module remains `235930f8d031c9d922afdeaff506cc62c583bcf68fdfd549b69ab7e4bb719dc8`.

The synchronous factory `createTinyTransmissionStepper(THREE, renderer, {maxCaptureBytes:131072})` accepts only its fixed synthetic16-source65-packet fixture, sourceVersion2601/densityRevision3601. It checks the explicit capture reservation before input generation/copies, packs full owned padded Float32 input buffers, computes both original-double and packed-double CPU oracles, then creates CPU Three resources without `getContext`, uploading, clearing or drawing. The frozen public plan contains plain-array fixture/oracles and Uint32 **bit patterns** in `packedWords.packet/source`; it exposes no target/texture or live `prepare` path.

The three expanded shader strings and material/geometry state are identical to the actual current production factory at caps16/65/3072. Both map passes retain `uPacketCount=65`, source stride16, tileCount2 and partialWidth32. The second viewport therefore writes absolute addresses16..31 with packet64, while each original64-term packet sum and the final two-tile sum retain their association. No per-chunk exponential, new shader branch, packet slicing or accumulation blend is used.

Each `submit(index)` performs exactly one synchronous `renderer.render`; `readPass(index)` reads only the owned prefix, returns a new Float32Array and metadata/token, and does not advance. The next submission is blocked until matching `accept(index, stageToken)`. The external helper owns the timer/error/oracle admission before calling accept. `cancel(reason)` retires the pipeline; wrong ordering, read/render/FBO/link/GL/context errors also retire it and retain the first failure. There is no partial/live publication, even after all stages complete.

Every submission/read uses the established supported-Three target/viewport binding guard, including distinct READ/DRAW, draw/read buffer selection, logical/current rectangles, XR/shadow/clear/tone/exposure/output state, all PACK/UNPACK fields, both pixel-transfer buffers and COPY_READ. Upload/read state is temporarily neutralized and restored. Readback explicitly binds the owned target's DRAW framebuffer as READ while guarded. The wrapper does not pretend to preserve undocumented renderer program/VAO cache identity. Seven owned Three resources dispose once; the borrowed renderer/context/canvas are never disposed.

They prove expanded shader/packing equality, exact map addresses, unchanged prefix, same synthetic final bits, strict lifecycle, per-operation state restoration, fault stop and disposal. They do not execute GLSL, measure hardware, certify numerical optics or admit larger native requests.
