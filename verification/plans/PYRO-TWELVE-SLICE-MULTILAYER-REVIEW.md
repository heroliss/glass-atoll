## 3. 与primary及当前十型的关系

[三遠官方说明](https://san-en-fireworks.com/index/products/productse/)§3-1(b)明确多芯/外层结构，页面同时给green-to-red chrysanthemum的效果例名；[APA官方Pistil定义](https://www.americanpyro.com/display-fireworks-glossary)也区分内球与外球。它们支持“不同层和不同发光时程可以共存”的技术方向，不能替这12图补出准确型号/口径/燃烧数据。**多芯球形壳**与**多个子壳稍后再次爆开**也不同；仅凭圆圈层数不能默认采用multi-break子事件。

当前源码快照physics3bbac197/FW963bc4fe，详见[前轮源色/HDR复核](PYRO-SIX-REFERENCE-COLOR-HDR-REVIEW.md)：

| 现有类 | 已有机制 | 与本序列的差别 |
|---|---|---|
| peony/chrysanthemum | 单次球形radial roots；固定body色；菊有尾迹 | 没有通用layerID/独立层速度和多芯profile；单层整体换色不能形成06–08同时异色的层。 |
| willow/palm | 现成的较长life/大臂及thermal尾迹，受重力/阻力下坠 | 是晚期形态可复用基础，但没有同一发里的彩层→不同余烬时程，tail仍固定thermal和少数window档。 |
| ring/heart | 固定世界平面图案；ring有双色面部 | 是二维pattern，不应被扩大成面向相机的多圈贴片以冒充3D多芯球。已验收笑脸保持独立。 |
| crossette | parent真实split、child晚出生 | 可提供族谱/因果出生结构，但不是本图多芯的直接证据，不要为了层次默认每层二次炸开。 |
| strobe | 亮度闪烁，有frequency/phase | 有时序不等于有颜色life/多层；不能把蓝色变白全归strobe。 |

## 4. 最小新增模型/API（尚未实施）

建议先新增**一个opt-in多芯菊/球形profile**，不替换十型默认，不修改已接受ring；用现有总body预算分层先做结构因果对照，而不是立即按截图点数增到成千body。以下是接口意图，不是测得参数：

```js
shellProfile = {
  id: 'multi-heart-reference-v1',
  layers: [
    // Each is a real 3D population, not a screen-facing ring.
    { id, count, distribution:'sphere', radialVelocityProfile,
      drag, burnProfileId, emissionProfileId, emberProfileId,
      matterAllocationRef }
  ],
  burstFlashProfileId: null // separate optional source, default absent
};
sampleEmitter(body, age);                 // instantaneous reference RGB/I
sampleEmber(body, emissionAge, emberAge); // past release + subsequent cooling
```

1. 每层从同一真实burst附近起始，以不同radial velocity/drag形成大小层级，保真实重力/风；不在第一帧把几十米彩环直接放到指定屏幕半径。初版各层可同birth；不能只因颜色显露较晚便伪造几秒点火延迟。`layerID`、bodyID、eventID、计数/谱/时钟和预算都可审计，观察者变化不改它们。
2. 光谱/强度由小型phase profile描述，可有点亮、可见彩段、燃尽/余烬，而非全部强制“先白→红→金”。保持一种固定原色profile的对照也能因重叠/曝光在早期变白；这是必须保留的反证。谱带/热余烬只做有来源或明确作者近似，不把黑体当蓝绿/紫的万能来源。
3. 先检验重叠stars＋现有积分PSF是否已经提供早期flash。若仍需要独立burst-charge flash，它必须是有限时空、入统一raw source账本和bound的真实光源项，默认0；不能另加屏幕白圆/glow并让照烟/云/地面另套增益。它也不代表同体积烟被点成自发光球。
4. tail应有head emission-age和ember-age两个时间；可按profile逐渐暖化/变暗，实际弯坠沿既有粒子动力学，不按期末把空间曲线重排成柳。不能把截图曝光拖线直接当固定几米长几何；短快门/长快门的差异应由成像积分产生。
5. 同一即时/过去sourceRGB必须进入主、mirror、曝光界、clusters/逐源ledger、volume field、cloud、GI；cameraC/P只影响存储/显示，不影响光谱phase或烟量。phase变化但位置不变时也要使受光缓存更新。动态RGB的快门上界必须覆盖所有tap/phase交界的最大通道。
6. 物质预算按[logical graph](PYRO-LOGICAL-SOURCE-GRAPH-REVIEW.md)独立分层/继承，不能从I或RGB推烟量。source representative/cohort覆盖全logical body与“每body独立Gaussian”分开，新增layer不自动加总M；旧烟仍可被后续B照亮，但不会变成A的物理轨迹。

### 成本边界

layerID/作者profile元数据本身可不增加pass，现有instancing/解析轨迹可复用；但更多body、tail片段、快门色采样、rawfield sources、persistent cohorts会增加CPU、overdraw与GPU bake。先固定旧总数分层测，不承诺匹配实拍的实际星数。source上限/field pair cap/两active事件和pending queue必须显式验，禁止超上限默删外层。可预计算小型色谱/年龄曲线，但不能只GPU染色而CPUbound/照明仍旧色。

## 5. 可证伪的最小实验

- **结构A/B：** 一个固定seed事件、同body总数/总参考I/物质量，A单层/B多层；固定FOV/相机/phase，以0/30/60/90度观察。若只有正面像多圈，拒绝3D多芯通过。不同层的世界D(t)/均值/drag/life可输出，不能用屏幕半径拟合。
- **显色反证：** 固定source RGB不变，仅改变物理展开/重叠和曝光；另做真实source phase变化。固定C、正确P补偿、相同DRT并保rawHDR及逐层source记录，明确哪些“露彩”可由去剪切产生、哪些需要发光颜色变化。不能据已tone-map的PNG反推原谱。
- **闪光来源：** 独立burstFlash0/1，保同一source ledger能量/时程定义；查看early.01/.03/.1 s（作者fixture时刻，不声称对应原图），确认P先降、无NaN/负值，烟/云/地表同phase响应，PSF峰界覆盖近视与重叠。不能只看一个白大球截图。
- **时间/尾：** 录完整展开→分层→衰减→弯坠，带应用physicalTime/burst phase；单发慢放与正常速度均看。相机固定，真实重力不改；尾采样数6/12/16应近似保同通量/轨迹，颜色跨快门phase边界需要独立oracle。
- **事件隔离：** 单发A与A+B配对。按eventID输出A的逻辑源/CPU头尾/范围，A指标不因B上升而改变。成像上光照/烟遮挡可相互作用，不能要求整个画面相同，但B不混入A运动/源强积分。这12参考中B区域不参与A的数字拟合。
- **预算与显示：** M/I绝对标定仍未完成；公开强度profile是作者reference。HDR/SDR以同float master、相同物理state分别输出；极值bit-exact不代表所有pixel bit-exact，也不代表实际HDR显示测量。照明够不够、颜色是否舒服最终仍需独立实际视觉验收。

本轮未实现上述API、未新增GPU/照片级验收。root已另取得timed实际16/16及HDR/SDR同phase/物理state、preDRT极值一致的证据；那是已完成时程/输出隔离范围，不能冒领这里尚未实现的多层、真变色或全像素相等。下一阶段应在该冻结检查点上单独选一个profile，避免同时改flight/烟扩散/DRT使因果混淆。

## 7. 两事件光源—共享烟—固定曝光合同（研究方案，未实施/未验收）

### 7.1 源与物质分账

保留独立事件`A/B`、logical body/child ID和raw source账本。令入射光为`L_A(t)+L_B(t)+L_base`，物质为共同的`rho_A+rho_B+rho_history`；两者不能以event ownership绑定成“某发只照自己的烟”。B启动不清A烟，A发光active槽退休也不删除A的冷烟。现有长时共享状态可以作为基础，不需要为了这项实验重新发明烟质量单位；参考干消光面积仍是作者relative units，非已标定kg。

同一固定介质下，单次散射对**入射源项**是线性的；消光由共享密度决定。冷烟不是额外自发光光源。实际实现仍有trace-isotropic packet场、有限source→smoke消光/条件均值等近似，不能把通过本合同说成完整RTE/多重散射正确。云是另一套天气密度，不将被照亮烟硬当成低云；flash不进入长期skyCube/PMREM。

### 7.2 最小两组实验，先隔离再连续

**冻结物质的2×2受光实验：** 选择A已有烟且B位于实际flash/彩色展开phase的一个真实paused状态，保存同一份共享烟snapshot、全部body pose/age/raw spectra、UTC/天气、镜头和cameraC。只控制两个事件是否向受光账本贡献，采`00/A0/0B/AB`四种模式。不得用重发/清烟/重算不同seed替代四次受光开关；不改变可见星I、source emission profile或烟M以补结果。若希望只检验受光，可遮住直接星像的ROI，不能删掉它的照明源。

应观察到：`0B`会照亮归属A/历史的烟；A source关闭不妨碍B照它；烟的M/均值/协方差/temperature/birth clock不因光源开关改变。记录线性raw SH/受光值或pre-DRT增量来检查叠加，基底只计一次。**不要求PNG满足`AB-A0-0B+00=0`**：ACES/gamut/编码、有限精度与显示是非线性的；即使线性图测试也应固定介质、PSF/曝光/存储补偿及所有源→介质路径，不能跨不同snapshot求差。

**两事件连续时程：** 在同一固定相机与实际C下录A展开/余烬→B发射与flash→B彩层→两发退光，应用自身时钟输出完整轨迹/发光记录。时刻是作者fixture，不冒充这23张的秒值。至少在B开始前、B flash、彩色中期、两发弱光/退休后保snapshot；旧烟可以扩散/漂移，不能因“画面暗”或active=0归零。若要验证已存烟仍可见，在最后同一snapshot重新启用一个先前合法的测试入射源，仅检查再照结果，不向正式事件时程伪造rebrightening。现有两active上限保持，后续未知C不混入这一实验。

### 7.3 真正固定C；P安全自适应不是曝光变化

当前`main.js:688–694`的自动曝光会按active烟花将targetC cap到16.5，active退休后又以另一适应时常返回夜景；灯/手电也能改变cap。因此固定UI EV补偿或固定UTC**不等于固定cameraC**。合同采用根代理计划的QA-only绝对camera EV lock：`null`默认无效，fixture锁最终C16.5（不是把UI EV补偿写16.5，也不是继续叠加夜景recommended EV）；验收每帧记录最终`photometry().cameraEV`并检查相等。锁的入口和实际行为仍须独立运行验证，本文不称已经实施通过。不得用“按钮看起来相同”当已固定。正式用户自动曝光另录一段，仅评估摄影呈现，不拿来推物理源衰减。

storageP可按全链headroom正常变化，必须记录其值并做正确显示补偿；不要为了同P覆盖安全预算。四种模式使用相同cameraC、源原始单位/参照、白平衡和DRT；保存raw受光/场系数及HDR范围。HDR/SDR仍从同一float master各自输出，不从截图反推绝对cd/nit。固定曝光实验也不意味着自然观看应始终无自动曝光。

### 7.4 归属、合并与镜像的必要边界

- `pyro-smoke-state.js:49,56`目前跨source合并会令`sourceId=null`，只保总M和低阶矩，并不完整保留事件物质祖先。首个两事件归属fixture应使用足够容量并证明无跨source merge，或用独立排放/消耗账本证明A/B分配；不能在已合并snapshot上过滤sourceId后说“A质量消失”。总M/总矩仍可检查，不能把丢归属元数据说成丢物质。
- 事件隔离按event/body ID，不按颜色、画面中心或哪点最亮。B08–B11下方未知上升迹不用于A/B的最低点、再次点火或能量曲线；原图定量ROI必须排除该区域及UI/字幕。模拟两事件fixture不新增第三事件去凑图。
- 主与mirror使用同一physicalTime、烟snapshot和raw source账本。镜像视线在真实water-hit起算有限空气/烟，非虚拟mirror eye全路径；入射source→smoke与出射smoke→eye各一次，不因reflection再排烟或给源再次乘P。当前近似路径需在报告标注，不把镜像看起来亮当已证明光程。
- 同一snapshot切换lighting时使resolved field/bound/接收表面及镜像缓存同步失效，不等待陈旧cube；TAA/history重建误差须与实际源差分分开。保留off重复帧底噪，不以任意放宽像素阈值掩盖缓存/时钟变化。

### 7.5 有意义的通过/失败门

1. 源/状态：四模式physicalTime、pose、年龄、完整烟snapshot一致；只受光启用位不同。总M/归属账本不因开启B、A退休或镜像capture改变。source范围、谱/phase及所选模型明示，source→smokeT尚缺时不得写已实现。
2. 因果：已有A烟在B照明下产生非零、空间位置正确的raw增量，源色改变不改M；减少/关闭光后烟可以变暗，但快照没有随像素黑而消失。若raw增量本来太小，报告不可见/未达到，不另加无来源gain。
3. 显示/数值：实际C固定、P自然安全、主/mirror全HDR有限非负且在headroom内；原PNG、snapshot和source/input hash保留。pre-DRT线性核检查与最终PNG可见检查分报，不能以极值相同代替全像素一致。
4. 视觉：完整连续记录须看清旧A余烬/烟与B新展开的空间关系；由人工独立判断是否仍是棉球/团花、颜色是否平板。技术守恒通过不等于烟花/烟照片级通过；本轮23张实看本身也不是实现验收。

这轮只冻结研究结论与验证合同，未改runtime、音量、源强或DRT，未实现多层shell/动态发光profile，也未声称上述两事件fixture已执行。
