## The280m receiver discrepancy stays a named independent change

Local/native/custom water/air and transient indirect currently use the finite280m window `max(0,1-(d/280)^4)^2`; clouds and resolved smoke have no identical hard distance cutoff. The radius regularizer is a near-source approximation, not a propagation range. A brighter flash does not make the range discrepancy disappear: beyond280m the affected paths still receive exactly zero.

First test the radiative source with the existing range policy and record this limit. Then compare a separately versioned firework receiver policy with an explicit unbounded inverse-square mode. Three's native `distance=0` means no cutoff, but the custom/indirect code presently uses `max(range,.01)` and cannot accept0 as the same meaning without an explicit branch. Native PBR, custom water/air, reactive masks and indirect must change together. No new cubemap shadows or infinite ambient are implied. This separate policy avoids attributing a simultaneous propagation-range change to the flash's peak or waveform. Distant illumination still needs the appropriate air/cloud/smoke transmission; source intensity does not justify repeating or removing transmission factors.
