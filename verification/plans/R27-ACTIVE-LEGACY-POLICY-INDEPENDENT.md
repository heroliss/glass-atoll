# R27 active-count and legacy comparator policy

`r27-active-policy-independent-check.json` records **3/3 CPU-only checks passed** against frozen R26 pure planners. No production change, native capture, browser or GPU submission is included.

Preserve the incumbent `maxPairs` option, its default3,072 and its old limit1,048,576. A separate optional `maxRequestPairs` may explicitly select the new active-count allowance up to1,400,000; omission means `maxRequestPairs ?? maxPairs`, preserving old callers. Keep a production default `maxMapDraws:8` for maps, with reduction counted separately. A native-specific three-map fixture allowance must not become that production default.

For global18,000 source /4,096 packet capacities, the independent check enumerates every positive packet count at its maximum feasible source count for each request allowance1,048,576 and1,400,000, under both conservative per-map ceilings1,000,000 and1,048,576. Maximum active cells are32,262 and36,000 respectively, each fitting compact allocation. For fixed packet count, cells grow monotonically with source count, so these maxima bound all smaller feasible source counts. With width256 and the stricter1,000,000-slot map ceiling, each full-row map holds61 rows. An address-zero interval decomposes into grouped full rows plus at most one end-row prefix: at most `ceil(floor(maxCells/256)/61)+1`, which is4. The looser1,048,576-slot ceiling also needs at most4. Default8 leaves no active-count regression within these declared domains.

The explicit old-domain regression is **16,131×65 =1,048,515 logical pairs**. At1,000,000 conservative slots per map, its32,262 tile cells require **four maps plus one reduction**:256×61 rows, another256×61,256×4, then6×1. A three-map policy rejects an old admissible logical request.

The `legacy-max` QA comparator has different padded work. For one source and4,096 packets at global capacities, it uses1,152,000 partial cells and73,728,000 conservative slots despite only4,096 logical pairs. The active-count eight-map proof does not cover that padded comparator. The minimal compatibility choice is a dedicated historical two-pass legacy-max path under unchanged logical `maxPairs<=1,048,576`, rejecting an explicit larger request allowance in that mode. Retain this explicit comparator scope rather than silently rejecting old QA layouts under the new active scheduling rule.

Source/packet inputs and shaders can remain unchanged; only request-policy plumbing, exact global-index rectangle dispatch and final complete publication need promotion after separate native GPU admission. A per-map ceiling is a current calibrated policy, not a permanent user constraint or a total-frame performance guarantee. Main-view T, reflected T and resolved smoke lighting retain separate counts, allocations and validation.
