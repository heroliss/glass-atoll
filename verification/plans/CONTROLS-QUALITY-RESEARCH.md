# 控件与五档画质研究

**状态：Round 1 draft；未获实现准入。** 本文是当前代码的只读盘点和候选方案，不是已实现功能清单或实测性能报告。根代理发布总计划前不修改运行时。Round 2 反方审查见末节，待与烟花专项研究交叉核对。

## 1. 当前接口与耦合

盘点范围：`main.js`、`ui.js`、`index.html`、`lens.js`、`quality-governor.js`、`shadow-quality.js`、`spectral-waves.js`、`caustics.js`、`water.js`、`sky.js`、`aerial-perspective.js`、`indirect-lighting.js`、`render-benchmark.js`。界面参考现有 `style.css` 与 frontend-design 的“沿用现有产品、让场景优先”原则，未改样式或源代码。

| 功能 | 已有实际接口/状态 | 当前限制或隐式影响 |
|---|---|---|
| 总画质 | `onQuality(high/balanced)` | 同时改 caustics、sky、lens、DPR、water RT；不是五档公共接口 |
| 像素 | `resize()`，`renderScale`，governor | high DPR 上限1.65、balanced上限1；内部q由governor控制，默认关闭自动；缺独立DPR/固定q设置接口 |
| 主MSAA | lens查询RGBA16F/R16F/DEPTH24共同样本数 | 当前high请求8、其他4；缺任意合法样本数setter；人为逐帧jitter默认关闭 |
| 阴影 | `shadowQuality.setQuality` | 2048/4096/6144/8192；限制到设备纹理尺寸。单方向图，不是PCSS/CSM |
| 海谱 | `waveSpectrum.setResolution` | 实际支持256/512/1024；默认512。256个模态、物理增益与时间应保持 |
| 焦散 | `caustics.setQuality` | balanced=768网格/1024纹理/15Hz；high=1536/2048/30Hz。初始化可为24Hz，远近距离还会自动切档，不能只凭high名称重现配置 |
| 水反射 | `water.resize(w,h,quality)` | high完整尺度、最多2×MSAA；balanced .65尺度/无MSAA；折射RT跟随内部像素。无独立比例setter |
| 云/大气 | `atmosphere.setQuality` | 已有low20/balanced32/high64云步；大气为6/8步；改变define会触发程序重编译 |
| 近空气 | `aerial.configure({quality})` | high8步/2个树影tap，balanced6步/1tap；半分辨率积分。现有quality不能独立修改体积尺度/步数 |
| 间接光 | `setQuality(off/low/high)` | 关/一次2Hz/两次4Hz；是太阳驱动SH1缓存，未包含新增局部灯或完整水界面GI |
| 镜头 | `lens.configure` | 焦距/景深/手动或中心对焦、SMAA、叶片/水时域、微散射均实际存在；摄影参数不宜被画质档覆盖 |
| 显示 | `resolveHDRCalibration` + `hdr.configure/setEnabled` | 自动/SDR/HDR、选屏、系统/手动nits已存在；应独立于画质。Windows原生数据是报告值而非测光 |
| 相机 | `moveTo`、navigation、Alt pivot、Home | 视角预设应只控制相机，保持日期/天气/曝光策略 |
| 时段 | `setNightPreset`、`setNightScene` | **现预设同时改太阳、云量、日期、自动曝光、相机**；用户要独立维度时必须拆开 |
| 天气 | `setWeather`、air/wind/current/sea状态 | 天气、海风、远涌浪、潮流已有独立参数；新预设不能暗改太阳/日期/相机 |
| 地灯/手电/烟花 | 无现成业务API | 标准材质可接Three局部灯，但水与空气是自定义主光路径；仅新增PointLight/SpotLight不足以完成一致效果 |

当前天空环境cube为256；一次更新一个面，12面/秒，PMREM间隔约2秒。这是现状而非接受原样的结论：**Round2已将跨面曝光/时间一致性列为前置阻断项**，不能只讨论频率而不处理捕获快照。手动时间变化已有强制刷新路径。

## 2. 五档候选——采样设置，不是五种天气

所有档保留相同场景尺寸、模态、风/涌浪/潮流、太阳/时间/天气、参考白/峰值和镜头创作参数。初版均固定q=1，**自动像素仍独立、默认关闭**。表中DPR是上限，不会把DPR1设备强行超采样。

下表是可证伪候选，未benchmark；“需解耦”表示现接口不足，不能把profile id直接塞进旧`quality`字符串。名称暂定，默认第三档。

| 采样项 | 1 流畅 | 2 均衡 | 3 标准（当前基线） | 4 精细 | 5 极致 |
|---|---:|---:|---:|---:|---:|
| DPR上限（需独立setter） | 1 | 1.25 | 1.65 | 1.65 | 2 |
| 主MSAA请求（需解耦） | 2 | 4 | 8 | 8 | 8 |
| 太阳阴影边长 | 2048 | 4096 | 4096 | 6144 | 8192 |
| 四张海谱边长 | 256 | 256 | 512 | 512 | 1024 |
| 云步/大气步 | 20/6 | 32/8 | 64/8 | 64/8 | 64/8 |
| 焦散网格/纹理边长 | 768/1024 | 768/1024 | 1536/2048 | 1536/2048 | 1536/2048 |
| 焦散更新上限（需解耦） | 15Hz | 24Hz | 24Hz | 30Hz | 30Hz |
| 反射尺度/MSAA（需解耦） | .65/0 | .75/0 | 1/2 | 1/2 | 1/2 |
| 近空气步/树影tap | 6/1 | 6/1 | 8/2 | 8/2 | 8/2 |
| GI太阳漫反射 | 关闭 | 一次/2Hz | 一次/2Hz | 两次/4Hz | 两次/4Hz |
| SMAA、叶片时域、水面短历史 | 开启 | 开启 | 开启 | 开启 | 开启 |
| 微量镜头散射 | 关闭 | 开启 | 开启 | 开启 | 开启 |

决策说明：

- 当前high不是可直接重放的第三档：初始化焦散24Hz，与调用high setter后的30Hz不同，远近自动档也会改变它。实施前要明确“档内允许的自适应”和诊断中的effective值，验证时固定策略。
- 第一档关闭GI会改变低频照明，是明确的精度让步；不补一盏不受约束的环境灯伪装亮度相同。
- 保留两种时域是候选，因为关闭叶片历史未必释放当前三附件MSAA内存，且水历史仍需同一全屏pass。若要最低档真正减少MRT，需要另立结构方案，不能只关checkbox并宣称带宽已经省掉。
- 不把“极致”定义成所有数字翻倍。暂不提2048焦散网格：1536→2048会从约472万三角形/次升到839万，边际收益和顶点/带宽成本未测。第五档已有海谱/阴影/像素上限的明确差别。
- 60/30/24是独立预算目标，不是档位的实测成绩。可以建议精细/极致尝试30/24，但不偷偷切换用户目标或自动像素开关。
- HDR、景深、自动夜间曝光、局部灯数量不由档位擅自改变。改高级采样后显示“自定义（基于标准）”，不能仍声称与标准档完全相同。

### 可预判成本与不能预判的部分

1. 像素数近似随DPR²×q²变化（q为内部线性分辨率比例）；这只是工作量关系，不是GPU毫秒预测。1.65→2的像素数约增加47%。
2. 当前主RT有RGBA16F颜色、RGBA16F运动、R16F覆盖深度及深度附件；MSAA样本数会放大存储/带宽。实际驱动分配、压缩和驻留不可从`renderer.info.memory`对象计数当成显存字节。
3. 阴影4096→8192有4倍texel，点光阴影另需最多6个方向；材质/光源数量也影响重绘成本。
4. 海谱256→512→1024每级是4倍场纹理面积；每个band像素合成其64个模态并生成mip。主模态与能量不能随档减少。
5. 焦散768与1536网格分别约118万/472万三角形/次，更新Hz再线性影响提交频次；实际裁剪、带宽及shader时间须测。
6. 云成本与覆盖像素、穿云长度及提前终止相关，不能把64/32步当作整场必然2倍。夜间、日落、逆光与高覆盖各需测试。
7. GI已有固定初始化代价，切档后的缓存求解频率与反射次数是CPU成本；不能把一次初始化日志当成每帧成本。

## 3. 最小公共接口与提交方式

建议由一个controller管理状态和副作用，而非各DOM事件重复串接多个setter。以下均为**拟议接口**：

```js
await controlsController.applyQualityPreset('standard');
controlsController.getQualityState(); // requested/effective/capabilityLimits/custom
controlsController.setView('shore', {animate:true}); // 仅相机
await controlsController.setTimePreset('moon');     // 仅时间/太阳，保留摄影偏好（R2修订）
await controlsController.setWeatherPreset('clear'); // 仅大气/海风；不改远涌浪和潮流
controlsController.setInteractionMode('focus');     // 单一指针模式
controlsController.setEffects(patch);               // 灯/手电；未准入前不可用
controlsController.launchFirework(options);         // 一次事件，后续专项准入
```

renderer最少要补的能力接口：独立DPR上限/主MSAA请求；caustic网格/纹理/Hz；反射尺度/样本。其余先适配已有setter，不扩为一个包罗所有shader参数的公开对象。硬件MSAA应选“共同支持且不大于请求的最大合法值”；不能只`min(request,maxSamples)`，因为支持集合可能不连续。超尺寸/显存失败需回退并报告effective档，不能让UI假装8192已经生效。

局部阴影还会增加纹理采样器。应逐program查询活动sampler、实际纹理单位与附件限制；不能只按声明数或桌面设备上限估算，更不能新增多个point/spot shadow后只检查JavaScript语法。

切换应在帧边界事务提交：先解析硬件与选项、准备资源/编译、再同步状态、失效历史/暂停缓存、绘制一帧。保留原配置直到有可恢复结果；但大RT不可全量双份预分配而不计算峰值资源预算。失败恢复原档并给出具体原因。不能清空当前投石、漂叶、模拟时间或换随机种子掩盖过渡。

## 4. 独立视角、时段和天气

现有284px轻面板、44px触摸目标、details展开/手机滚动机制继续使用。建议顶部只保留“画质”一个5项选择，下面“视角 / 时段 / 天气”各自独立，摄影/显示/效果放入折叠区；无需新巨幅HUD或装饰卡片。

- **视角**：沙滩、浅海、俯瞰、仰望天空；只写camera/target。若提供“朝向月亮”，根据当前月位构图，月亮在地平线下时提示当前不可见，不暗改日期。
- **时段**：晴日、日落、月夜、无月夜，只写对应太阳/天文日期。R1曾考虑连同夜间曝光策略切换，Round2已否决：不改用户的automaticExposure布尔或userEV；用户已开启自动时才让新UTC驱动recommendedEV。当前太阳是独立艺术指向，不能改一个datetime就宣称已实现真实太阳周日运动；完整天文太阳模式需新增接口、验证后再准入。
- **天气**：清晴、薄云、积云等只写湿度、温度、云底/厚度/覆盖与海风；海风影响树/云/短风浪是已公开的物理联动，远涌浪与潮流继续独立。不能为了“晴日”自动移走相机或抹掉用户灯。
- 原“暗夜星河”同时调整云与相机，若要保留作快速摄影组合，应明确放在独立“组合场景”，逐项说明将改时间/天气/构图；不能伪装成独立时段。
- 每次只更新所属状态域。Home只恢复相机；“重置场景”才可同时重置各域，且保留/清除局部效果的行为要写明。

## 5. 地灯、手电、烟花的可用性边界

目前没有这些业务模块。Three标准材质接PointLight/SpotLight只能证明地表可能被照亮，不能证明自定义水、空气、反射与预曝光都一致。

### 最小光照契约

建议共享 `LocalLightState`：稳定id、point/spot种类、世界位置/方向、线性RGB、candela、锥半角/软边、有效范围、是否投影/阴影及路径参与标志。UI先给开关、亮度、光色、位置/随镜头；高级物理参数折叠。所有灯数与逻辑发射器数量独立于画质，不因降档静默少亮几盏。

当前场景太阳单位未做绝对lux校准，夜间有`preExposureEV`。新灯必须通过同一线性光照/预曝光转换；不能直接把cd当scene intensity，也不能在最后display exposure之外又乘一次。转换用的参考太阳lux若属假设须可见记录，不能宣称整场已绝对测光。

Three本地源码中PointLight的power=4π×intensity；SpotLight的power=π×intensity是实现约定，不是任意锥角下的均匀锥体固体角积分。第一版以candela存储，若UI接受流明则先定义并积分实际光束形状，不能一边改锥角一边意外改变总能量。

- **地灯**：放置模式需选实际干地表、显示真实米制尺寸；先限定固定数量池，而非无限创建。发光壳体与照亮表面需一致，不能只出现发光球。point阴影6视向成本必须单测。
- **手电**：跟随相机，在导航更新后更新位置/方向；照亮地物、水面/水下、近空气分别列能力。现水着色只算主方向光，空气也只查主光/树云遮挡；这些接入完成前不能把checkbox标作完整可用。
- **烟花**：交由专项研究定义弹道、发射/爆裂/余烬/烟雾与光声。单次发射按钮优先；不自动重复、不默认夺走相机，不擅自启声音。若提供跟随构图，单独开关默认关闭，手动输入立即退出跟随，但不删除已发射的物理事件。
- 普通点灯直射、可见发光几何、反射中的发光体、体积散射必须由同一发射器描述；GI目前仅太阳驱动，不能把局部灯照明假称已经进入现有两次反射。

### 操作冲突约束

只允许一个canvas指针模式：默认观察/点水投石、点选对焦、移动pivot、放灯、指定烟花位置。Esc取消并把焦点交回canvas；UI输入/选择保留原生键盘。不能新增一个“点击地面”handler与已有水面投石同时触发。自动烟花跟随与已有pendingThrow/transition不能争夺同一camera：需要统一camera intent及cancel reason。

## 6. 验证协议——先固定条件，再比较

1. **状态独立性**：对5×视角×时段×天气组合做状态差异检查。改quality不得改日期、太阳/天气、相机、声/灯开关与物理能量；改view不得改time/weather；改time不得暗改view/clouds。
2. **能力与资源**：逐档记录请求/有效MSAA、附件格式、输出/内部尺寸、各RT/阴影/谱纹理大小、shader日志、活动sampler数、分配失败回退；低档/高档来回10次检查泄漏和黑画布。不能只读UI选中项判生效。
3. **固定回放**：相同seed/time、镜头轨迹、日落/月夜/暗夜、高覆盖、投石/漂叶与未来局部灯/烟花；切档期间不改光照强度。颜色与帧间误差同时看，不能靠变暗减少闪烁。
4. **基准**：每档预热至编译/GI/历史稳定，再做多个12–20秒窗口；记录rAF间隔p50/p95/p99、超预算比例、CPU、GL GPU与所有有效设置。拒绝paused/缓存呈现作为持续渲染基准。录屏30/60fps、rAF计数及同步readback墙钟都不能冒充实际渲染FPS。
5. **HDR全链路**：GL计时不等于WebGPU浮点复制/显示合成的完整时间。HDR/SDR分组记录，继续用独立OutputPass与nits oracle；已有20项是模块数值证据，不是五档性能结果。
6. **近景与边界**：重点检查叶脉/树干、低角度海面、湿沙、火花亚像素、薄雾与灯束遮挡；固定PNG和连续片段分别验。保留均值、动态范围及空间/时间结构，不能只用单个SSIM或“肉眼更柔”代替诊断。

**本研究没有执行五档benchmark，表中没有FPS成绩。** 只有既有接口/代码与历史独立夹具作为依据，未来指标应在根总计划中确定后执行。

## 7. Round 2：独立反方（交叉研究前）

以下会主动推翻Round1假设，尚未得出实现结论：

| 待推翻的假设 | 失败方式 | 可证伪检查 |
|---|---|---|
| 低粒子数乘N比例即可保亮度 | HDR肩部截断更亮的幸存粒子，画面总亮度反而下降；轮廓变成大点 | 在tone-map前积分同事件RGB×像素立体角×时间；另比tone-map后亮度分布/点尺寸，不能只有Σintensity |
| 灯+发光粒子同时开启总是更真实 | 水平面反射已含发光粒子，又加其解析镜面项，重复同一路径 | 发光体可见性/解析高光四状态A/B，测同一镜面方向的线性增量；每条路径只选一种表示 |
| 自动构图让烟花更容易看见 | 抢右拖/Home/点对焦或投石近看相机；用户输入后镜头仍被拉回 | 跟随开/关时分别在发射/飞行/爆裂阶段输入；camera intent立即转用户，物理事件继续 |
| 五档只减少粒子/光源就是低成本 | 删掉灯改变物理场景；独立cd与粒子emissive不相干 | 切档后逻辑发射器id、总功率/发射时序不变；只渲染表示可变，必要时聚类并保持角分布 |
| 曝光后再加亮flash可避免夜间下溢 | 绕开水/空气/材质，HDR/SDR不一致且重复预曝光 | 固定preExposure EV做等效性测试，最终显示不随内部预曝光选择改变；地表、反射、空气同步 |
| 主场景8×就是烟花已抗锯齿 | 亚像素火花/高速轨迹仍漏采，现motion捕获仅支持植被 | 固定世界火花尺寸跨距离/像素q测试，物理有限曝光轨迹积分与覆盖归一；不放大成大球或强行进叶片TAA |
| 微散射亮光多就代表能量更多 | PSF已做辐射重分配，额外添加辉光会双加 | 重跑点光通量夹具，比较新增效果开/关的线性delta，不让阈值光团无界增能 |
| 相同HDR峰值使每档亮度自然一致 | 颗粒LOD/烟雾/采样覆盖改变进显示曲线前的能量，峰值相同也会有不同曝光观感 | 保持paperWhite/peak/exposure相同，统计线性源能量及显示后分位数，不能只比较峰值 |

Round2还需阅读烟花专项文档并记录分歧。最终何种路径负责水面反射、地表光照、空气与阴影，以及哪些能力允许按档降低，须由根总计划统一，不能先落代码再补标签。

## 8. Round 2 交叉审查：已读专项研究，仍未定案

2026-10-26已读 [FIREWORKS-RESEARCH.md](./FIREWORKS-RESEARCH.md)、[LOCAL-LIGHT-AND-INTEGRATION-RESEARCH.md](./LOCAL-LIGHT-AND-INTEGRATION-RESEARCH.md)、[00-ROADMAP.md](./00-ROADMAP.md)，并收到天体侧关于时钟/曝光缓存的交叉意见。以下是对候选的反方结论，不是实现结果。

### 8.1 主动推翻自己的R1假设

| R1假设 | Round2处置 | 原因与R3条件 |
|---|---|---|
| 时段可一起切曝光策略 | **推翻** | 时间不应重置用户automaticExposure/userEV；只在原本自动时改变推荐EV。组合摄影按钮另行显式说明 |
| 旧cube/PMREM频率可以先不动 | **推翻** | 加速UTC且21EV变化时，六面若不在同一捕获曝光/UTC下，单个ratio不能修复整张cube。先做同快照back-cube/front原子交换与曝光标签，再讨论档位Hz |
| 首版地灯需要自由放置模式 | **撤出最低范围** | 用户核心是三盏实体地灯可调亮度/颜色，固定稳定位置即可；自由放置会增加与投石/对焦/pivot争用，不是前提。除非总计划明确纳入，不新增该指针模式 |
| 烟花自动构图默认关闭 | **改为未定默认** | 这是R1偏好假设，非用户要求。进入“观看演出”可以是明确的自动构图动作；“发射”是否跟随要由总计划定义，不能隐藏副作用 |
| T1关GI仍能保持跨档氛围 | **受挑战，暂不接受** | 会改变阴影区平均照明。若目标是跨档同色调，T1应保留一次反射、只降低求解频率/精度；现off/low/high接口不够，不能用补环境灯掩盖差异 |
| 粒子/烟/光簇数量是普通质量旋钮 | **推翻直接删减** | 它们分别改变光能、光学厚度与接收面照度，不是单纯采样精度。须有固定逻辑事件和有权重的渲染表示 |

第三档仍只是当前基线候选，五档表不能据此宣称已经科学定案。维度独立性也必须包括摄影偏好、地方时/UTC、云密度模拟秒和捕获调度，不能以“换成夜空更快”证明某档优化。

### 8.2 烟花质量降档与HDR预算的反证

专项的十类机制、物理秒、归一PSF、局部照明簇和独立声事件值得保留；但`setQuality({maxStars,trailSegments,smokeSprites,lightClusters})`目前只描述容量，没有定义守恒映射。

**逻辑事件不变，渲染代表可变。** 同一seed的爆点、星体初速、分裂、燃烧曲线和源颜色/功率须与tier无关。降低`maxStars`不能截断事件图；代表点的权重不仅要守总功率，还需控制角向/时序分布。动态光簇的Σcandela相同也不保证接收点照度相同：`Σ I_i/r_i²`通常不等于把总强度放到质心的结果，近处尤其明显。须在沙/水/树冠接收点上对完整源求和作误差对照。

烟的相应量是质量/消光积分`τ`，不是Σalpha。减半烟片后把alpha乘2不能一般保持`exp(−τ)`或散射；低档宜降低同一密度场的着色分辨率/积分样本，或明确验证聚类核的质量、投影光学厚度与透射误差。现两个云形A/B已证明“形状变薄”可能同时改变总密度，这个教训不能在烟里重演。

专项A方案可作为受限候选，但“最近距离+同时发数”还不够锁定FP16上界。未解析源`L_pixel≈I/(r²Ω_pixel)`，DPR/内部尺度、70mm长焦、PSF支撑和视窗大小都改变Ω；从低档到极致，即使世界参数不变也可能提高像素峰值。自由相机还能在发射后靠近，不能只在launch时做距离检查。R3至少应选择：有限尺寸发射体/物理角PSF的全域上界，或有一致曝光标签的全链存储调整；不能在相机接近后偷偷调低源功率、删星或只降低最终display exposure（那已晚于FP16溢出）。

**必须可证伪：** 固定事件在所有tier、24/70mm、最小/最大视窗、远处与允许最近距离下测source→尾/烟→反射→合成→历史→DOF/Bloom的每个浮点场；finite与弱星保留分开检查。另对透明火花做归一PSF能量测试，防止RGB已经乘PSF而SRC_ALPHA又乘一次，变成PSF²。

### 8.3 四附件reactive候选：容量可用不等于混合正确

根代理只读实机记录 [LIVE-CAPABILITIES-R1.json](./LIVE-CAPABILITIES-R1.json)：fragment sampler16、draw buffers8，RGBA16F/R16F/R8分别支持8/4/2/1样本，uniform vectors1024。它支持继续研究第四R8附件，**没有证明四附件完整FBO/所有材质混合已经验收**。

现主颜色alpha承载water `.70` /leaf类标记，透明normal/additive混合会改它。新增mask应在water/leaf分类之前读取，bypass的像素同时写无效history metadata，防止粒子消失后旧颜色再回流。现motion是植被专用，不能把烟花塞进旧leaf history做拖尾。

R8候选仍有三类漏标：

1. **低alpha、高HDR**：opacity .001、RGB10000仍有可见贡献，R8若只存opacity可能量化为0。需要定义保守reactivity及片元覆盖语义，不能直接把透明度当响应度。MSAA解析后的mask也不能除以仅属于叶片的coverage，水/火花像素可能无叶coverage。
2. **间接可见路径**：只标主视图粒子会漏掉水中倒影、被爆闪照亮的叶/沙、空气源项。需要来自反射/局部光变化的receiver mask，或明确保守bounds方案；不能让一个MRT标记假称整条链都已无拖尾。
3. **history复用捷径**：如果lens在stillFrames分支直接复用历史，根本不执行mask shader；effect/light revision必须参加稳定性判据/历史失效。暂停时发射或开灯的策略也需定义，不能让新效果被暂停缓存吞掉。

R8没有存储alpha不代表可凭推测确定SRC_ALPHA：用实际材质检查输出alpha、global blendfunc、alpha-to-coverage、normal/additive/premultiplied和透明层叠的最终R8值。至少含：opaque背景→微弱强HDR火花→前景半透明烟；反序/重叠；1/8几何覆盖；alpha=0/小于1/255；火花走开；水/叶类别恢复；暂停后新事件。**不接受负R16F sentinel**：MSAA平均和additive数值都可产生歧义。

若需每附件不同blend，必须先查`EXT_draw_buffers_indexed`等实际能力，不能把WebGL2全局blendfunc误当成每附件独立。替代mask pass会增加场景重绘/状态成本，需要明确测量。此处不预先批准任何一种。

### 8.4 水已用满16采样器：保留太阳4096精度的候选排序

根代理对当前water盘点为：波4、SWE1、折射颜色/深度2、反射颜色/深度2、地形高1、焦散1、天空1、近/远云影2、太阳阴影1、沙色1，共16。**不能直接加第17个flash shadow sampler。**

**首选验证：近/远云影合为两层texture array。** 当前二者均256²、RGBA16F、无深度，形态/更新逻辑共享。`sampler2DArray`替换两sampler，以层0/1保留原矩阵、extent、UV/clamp与各256分辨率；不降低原太阳图。若直接分别渲染到两层，可以保持现有两个缓存绘制而不额外重绘。它把water占用从16变15，为一个**局部阴影atlas**腾出槽位；spot/未来局部阴影在该atlas内统一tile。各使用方需通过同一helper迁移，不能只改water而让叶/空气查询旧资源。

**必须验：** 原两图与新层逐texel/边界/插值对照、RGBA16F精度、所有材质链接、所有RT/层/viewport恢复、云影连续、sampler有效数、8×MSAA/FBO组合。共享array是WebGL2候选，不是现成已实现API。

**次选：太阳与局部阴影共用RGBA8 packed atlas/array。** 太阳保留完整4096×4096 tile和原depth packing，不把它缩入更小区域。PCF footprint仍按太阳tile texel计，UV只在最后映射到atlas；边界需guard且不能过滤packed深度。现Three的标准材质太阳图可保留原图，给自定义water/air做1:1复制合图；但4096图每次复制有真实带宽/内存成本。8192档加local tile还要检查最大维度；2D array可保尺寸但同尺寸层会浪费内存，不能默认为免费。

**拒绝捷径：** 不把RGBA packed太阳深度塞进RGBA16F云图并继续按原packing解码；高位通道的半浮量化会降低比较精度，画面尺寸仍写4096并不能挽救。也不为腾槽盲合并折射/反射深度进HalfFloat颜色alpha，那会改变深度精度与透明混合语义。

**明确的有限回退：** 标准地面/树叶接原生spot shadow；water不新增sampler，复用现地形高度查询做局部射线/地形遮挡近似，树冠可用有说明的有限体积近似。太阳仍保留4096精度。此路线必须在UI/验收写清局部水影不是逐叶spot shadow；水面局部高光、折射床面与空气哪些路径真正接通，逐项列出，不能把没有实现的照明称为完整支持。

反射reactive也不能无预算再加一张贴图。有可能复用反射颜色的未用通道或用保守反射bounds，但反射背景默认alpha、透明blend与alpha-to-coverage会影响该做法，须另做真实GPU fixture，不把主颜色alpha标签的旧问题换个位置再引入。

### 8.5 相机、输入与表面光照的路径责任

自动构图应消费同一烟花事件的未来可见包围体与当前相机，而非每类固定传送到一张漂亮机位。需要同时容纳岛/发射阶段/爆点范围；大时长Willow与近地Fan不能用同一球形界限。跟随通过统一camera intent写camera与Orbit target；手动右拖/WASD/Home立即接管，而已发射事件继续。禁止相机看不到就放大烟花世界尺寸，或把同一参考源朝相机旋成永远正面的Heart/Ring。

存在重复计数的明确路径：若平面反射已看见发光粒子，再给water叠同一源解析镜面项，相同光路被计算两次。粒子直视、照亮其他表面的漫反射、散射光路并不是天然重复，但需要记录每项由谁负责；不应把快闪写入慢更新PMREM后又加点灯。源event id应贯穿可见粒子、light clusters与声音，便于路径A/B。

三盏固定实体地灯、手电、烟花彼此独立：调日期不偷偷开灯，切quality不熄灯，天气不换源颜色；用户主动选“夜间自动地灯”时才使用该自动规则。音效沿既有声音总开关，不在第一次发射时擅自启用。

### 8.6 R3前阻断项与通过标准

- **E1 存储上界**：确定所有tier/FOV/距离/并发的FP16源级预算；否则A不能定案。保持弱星而又容纳局部亮光的策略需要同时通过上/下溢夹具。
- **E2 元数据与混合**：四R8 MRT的实际blend/coverage/history/反射receiver语义通过，不能以caps查询代替。
- **E3 采样器**：接受cloud-array或其他一条经实测的资源路径，实际water活动sampler≤设备上限，并保持太阳4096深度/投影精度。
- **E4 帧状态**：统一UTC、物理模拟秒、camera adaptation与audio时钟；环境捕获的同快照/曝光标签先于连续加速时间。
- **E5 质量守恒**：canonical event不变；粒子/烟/光簇降档各有辐射/光学厚度/接收面误差oracle，HDR前后分别检验，不用自动曝光掩盖差异。
- **E6 原生交互**：发射/拖动/蓄力/放弃/点选/pivot/自动构图不争用；真实键鼠与触屏序列后状态、物理轨迹与UI提示一致。

以上通过后再由根代理选择有限实现，不是要求先写全部技术。可拒绝收益小/无法在预算内证明的分支，保留准确边界；当前没有新增运行时代码或新性能成绩。
