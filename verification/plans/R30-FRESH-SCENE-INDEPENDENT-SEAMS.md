# R30 fresh-fireworks composition: independent source audit

Read-only design review before any new scene GPU gate. The authoritative R29 manifest `35b47da69cb0e486158048ec802a2d472658e33ca115c4c79f16cf989d0394c7` and its 33 runtime source pins matched at R30 entry. R29 made real, scoped progress: unchanged complete SourceT and SH kernels ran on original later-life native inputs and expanded the calibrated one-event request range. It did not prove evolving scene FPS, a real mirrored GPU workload, or accumulated fireworks performance. R29 sealed files must remain historical evidence after the deliberately separate R30 main QA seam is added.

## Measurement scope

The proposed first gate is one fresh fireworks/density composition through the real production callbacks in the existing paused environment. It does not advance all ocean, cloud, vegetation, celestial, navigation and audio simulation clocks. Those frozen environment clocks must be disclosed. The new owned event/trajectory host must reproduce the actual unmodified host recipe and causal physical update union; an assumed logical-all or other alternate smoke profile would be a different fixture. No user event or owned launch/burst should be forwarded to the live audio queues.

The root-selected output is SDR via `lens.render(...,{sdr:true})`. This skips `hdrOutput.present`, its separate WebGPU surface, external-image copy, and optional async-PBO presentation. It is therefore a composed SDR correctness/cost gate, not an HDR presentation or full normal-RAF cost result. The environment, materials, lighting and normal lens postprocessing remain production paths.

## Actual source paths and auxiliary work

| Path | Work to include |
| --- | --- |
| `updateScenePhotometry(0,true)` | Fresh SH once, two forced near/far cloud-shadow fullscreen draws, CPU GI/transient solves, local-light/atmosphere/exposure updates |
| `water.render(time)` | Refraction scene with layer 1, mirrored opaque scene without sky/water, optional reflected transient cloud, independent depth blit, reflected volume, reflected SourceT and matching firework draw |
| `lens.render` | Main opaque four-attachment scene, up to one temporal resolve, two aerial passes, thin-lens pass, main volume/SourceT/fireworks, five bloom passes, three SMAA passes, SDR output |
| Scene render internals | Indexed/instanced/material-group draws, eligible shadow draws, multisample resolves and target mipmap generation |
| Capture | One declared default-framebuffer to owned-FBO color blit immediately after lens return, inside the query; later bounded readback only after timing/state acceptance |

`prepareStarView` is currently a direction-space uniform preparation with **zero draws**. Vegetation motion capture adds attachments to the same opaque render, not a second geometry scene. GI update/prepareTransient are CPU solves, not extra `renderer.render` calls. Explicit reflection depth copy is a `gl.blitFramebuffer`, not a triangle draw. These distinctions prevent both missing work and invented passes.

The saved current-night inventory has 35 visible material draw units and 32 visible caster units, all mesh objects. Its ancestor visibility, material groups, transparent double-sided handling and zero-instance/draw-range checks give a conservative count for this scene. No light currently has `castShadow:true`; the sun has zero intensity. A dirty global shadow flag alone does not imply a shadow pass. Re-inventory after hiding the original launcher and adding the identically decorated eight-mesh owned launcher; do not enable a daylight shadow merely for this diagnostic.

A deliberately coarse night bound is `3 × visible units + numerical draws + 2 volume + 2 fireworks + 1 reflected cloud + 2 cloud shadow + 13 lens postprocess`. With 35 units and 18 numerical draws this is 143 triangle draws; the layer/culling-specific actual count should be smaller. Small-viewport adaptive source counts must be measured by the new CPU preplan, so 18 is not automatically the new exact count. A helper's hard actual-GL budget must include indexed/instanced and internal shadow paths rather than count only top-level `renderer.render` calls.

Pinned r180 resolves each multisampled color attachment after `renderer.render`: the four main attachments allow up to four blits; reflected opaque/cloud/volume/fireworks each allow one more. Independent reflected depth copy and the final capture add two, for a conservative **10 blits** in this branch. Multisampled-render-to-texture extensions may reduce the observed count. The reflected color target has generated mipmaps, allowing up to **four mipmap operations** for those reflected renders. Treat these as separate bounded operation categories, not extra scene triangle draws.

## Size and capture contract

`water.resize` clamps the reflection to at least 160×120. Root's 160×171 main/refraction/reflection selection respects that minimum while retaining the original camera aspect; a 160×90 target would not. `lens.setSize` alone leaves the renderer's default drawing buffer unchanged. The selected transaction explicitly saves renderer logical/physical dimensions, pixel ratio and canvas styles and calls `setDrawingBufferSize(160,171,1)`; restore those dimensions separately.

Detach the lens HDR pointer before temporary lens resizing, then reconnect it before the separately accounted original HDR restoration presentation. Lens resize also resets scene/history targets, SMAA, upscaler, bloom and motion history. Prior temporal pixels cannot be restored bitwise through the public API; restore original intent/dimensions and invalidate/rebuild history explicitly.

`sdr:true` does not itself reset native HDR drawing-buffer storage. The saved context is RGBA16F. Inspect the actual source size/format/sample count and capture to a matching single-sample RGBA16F or RGBA8 owned texture/FBO. The WebGL [EXT_color_buffer_float specification](https://registry.khronos.org/webgl/extensions/EXT_color_buffer_float/) explicitly permits RGBA/FLOAT reads from float color buffers and forbids RGBA/UNSIGNED_BYTE reads there. At 160×171 this is **437,760 bytes** for FLOAT or **109,440 bytes** for RGBA8/UNSIGNED_BYTE. No readback may be based on a preserved default buffer after yielding.

The native [EXT_color_buffer_float specification, copying-pixels amendment](https://registry.khronos.org/OpenGL/extensions/EXT/EXT_color_buffer_float.txt) permits fixed/float category conversion for color blits; float-to-normalized is not categorically illegal. Matching formats are chosen to avoid conversion/clamping ambiguity, not because the extension universally forbids conversion. Check complete distinct read/draw FBOs, matching dimensions, NEAREST, no scissor clipping, correct read/draw buffer selection and context identity. Raw texture allocation additionally needs ACTIVE_TEXTURE/TEXTURE_BINDING_2D restoration beyond the existing R29 framebuffer/PACK/UNPACK/PBO guard.

## Ownership, cancellation and restoration

Keep the original empty fireworks/smoke pair installed during yielded CPU replay and hashing. Fingerprint the entry user intent, camera, pause/interaction epochs and viewport before each yield and before swapping. Cancel before installation if those change, preserving the new user action. During the short owned installation/query/read/restore interval, root may save and set `body.inert` and `controls.enabled`; still check epochs because inert does not suppress every window key listener or direct API call. A resize must cancel output and restore dimensions to the current actual viewport rather than overwrite the newer size.

Keep the original launcher parent and sibling index intact by hiding it in place; add/remove only the owned rig. Apply the same cloud, GI and local-light material decorations used during initialization. Swap only root-owned references for the transaction. The SH host owns its new field, and both volume views must name the same fresh SH version/generation. Each SourceT prepare borrows an output texture; the matching sorted per-eye source draw must consume it before the next eye replaces it. Equal eye counts do not authorize equal rays or cached T.

`updateScenePhotometry` also mutates frameSnapshot, camera/storage-exposure state, atmosphere/local-light uniforms, cloud-shadow/GI caches and environment exposure ratios. Save root globals and restore original photometry through the production callback. Radiometry/cache epochs and prior temporal pixels are recomputed/reset, not bitwise restored; say so. No whole-environment texture backup is needed for this narrower declared reset contract.

Restore logical objects, dimensions and supported native state before any separate original empty-scene presentation. The successful restoration presentation and subsequent ordinary paused convergence are outside the measured transaction and must be accounted separately. Setting `lastPausedRenderKey=null` can cause 41 ordinary convergence frames; do not hide them as a single restoration draw. On GL/context/shader fault, do not submit more experimental or QA restoration draws; preserve the failure, restore CPU state where possible and handle ordinary recovery as a distinct action. A retrospective timer cannot preempt already submitted work, and neither its GPU interval nor cold instrumented CPU submission proves native-resolution 60 FPS.

The original lens target object can remain selected after ordinary HDR presentation. `lens.setSize` disposes that target's old framebuffer storage. Capture its semantic Three target/face/mip before installation and bind the default target before resizing; an entry raw framebuffer handle cannot be restored across this disposal. Capture exact native measurement state only after installation, restore that state before private disposal and bridge teardown, then rebuild original dimensions and rebind the saved target object with new physical storage. This promises semantic target restoration, not old framebuffer-handle identity.

The independent CPU execution in `r30-main-bridge-independent-check.mjs` runs the actual extracted bridge and entry hook with spies, including partial setup failure, multiple restore failures, current-window resize, guarded loading, paused failure caching, and separate original presentation. Its 9/9 receipt applies to the source hashes recorded there; it supplies no live state or pixel proof. Cleanup failures are accumulated by stage while original references, HDR connection and interactivity still receive restoration attempts.

Before hardware dispatch, root selected a **100 ms retrospective whole-frame interval** for this composed gate, retaining the strict 143 triangle-draw, 19.28-million submitted-element and 10-blit ceilings. This is a different measurement unit from R29's 25 ms isolated numerical jobs, not a changed user frame-rate requirement. Report 16.7/33.3 ms reference intervals separately. Passing 100 ms alone does not establish output correctness, acceptable visual quality, HDR cost, or continuous 60/30 FPS; shader/context faults, disjoint/timeout and operation-cap failures do not authorize an automatic repeat.

This is a source/design review only. A frozen helper, CPU preflight and root-owned bounded actual dispatch are still required; no R30 GPU admission is granted by this document.
