## 当前机位和两发积烟改变了下一步重点

[真实机位与积烟证据](R29-CURRENT-CAMERA-ACCUMULATION-COUNTS.md)使用保存的用户机位、实际水面反射相机和原生产物理，在 CPU 上重放；不运行多发 GPU 压测。

- 单发采样阶段：2301 烟团，主画面/倒影各 1402 光路，1399 SH 源。各请求约 322 万，三路合计 **9,671,103**，需要 **18 次数值绘制**，之后还有烟体、海岛、天空、水、深度与镜头处理。
- 两发相隔两秒：3364 烟团，主画面/倒影各 3112 光路，3101 SH 源。各请求约 1040 万，三路合计 **31,369,300**，需要 **39 次数值绘制**。82 个采样时刻越过 400 万；该峰值发生在密度合并前，不能用单发乘二推测。

主/镜行数相同不代表光路相同；遮光必须逐眼计算并立即消费，SH 则可共享世界空间同代结果。两发最后达到原有 4096 烟团容量并发生既有合并，物质量守恒；本轮没有缩短烟尘寿命或删除烟量。

已定位超预算路径：SourceT 在提交 GPU 前拒绝，随后每个光点同步进入 CPU 光路查询；查询已有 BVH/高斯支持区裁剪，不能将逻辑配对数直接等同实际 CPU 遍历次数。该回退仍可能造成主线程卡顿，本轮未测卡顿时长。SH 超预算不会执行完整 CPU 受光烘焙，而是退回现有局部灯/光簇近似，受光细节会损失。**400 万是当前单发校准范围，不是积烟解决方案或永久上限。**

下一步见[同代实际整帧方案](plans/R29-ONE-FRESH-SCENE-FRAME-DESIGN.md)：先进行一个可控的新鲜生产帧，确认同代 SH 只烘焙一次，主/镜 SourceT 正确消费，并计入烟体和全部场景后处理；再校准真实非零倒影和两发的更大完整请求，处理回退开销。现有冻结 benchmark 的 delta=0，SH 可命中缓存，不能拿冻结 FPS 代表动态受光性能。
