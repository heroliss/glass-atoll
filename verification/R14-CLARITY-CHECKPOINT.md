# R14 水体清澈度

已接入现有“海风与潮流”面板，默认90%。这是对已有按距离计算的水下吸收/散射增加控制，不是水面透明度滑杆。

`water-optics.js`保留作者RGB参考吸收 `[.160,.035,.018] m^-1`。90%时散射精确保留旧值 `[.004,.009,.014] m^-1`；清澈度只改变悬浮颗粒散射倍率，100%仍保留非零分子散射底值。透射为 `exp(-(a+b)*实际光程)`，同一系数进入视线、太阳入水、局部光水下路径与现有单次散射。它不是NTU、Secchi深度或完整实测光谱标定。

默认10m直通光的RGB透射约 `[.194,.644,.726]`；这是光束存活比例，不是“能看清物体的距离”。RGB近似使波长选择性可见，不能当成完整光谱模拟。系数和映射依据、原子验证及局限见 `r14-water-optics-design.md`。

新增两个vec3 uniform，无新采样器、RT、pass、波浪更新或shader重编译。`main.setSea`先验证clarity，随后同步材质和UI；只改清澈度时跳过波谱/边界涌浪/焦散重新生成，只重置必要的画面历史。画质档位不包含此参数。

## 已完成的实际验收

- CPU/factory6/6；UI结构回归22/22。
- 原有健康renderer上的128×64实际GPU传输核5/5，GL[]：旧literal/新uniform浮点误差、实际距离、清澈度、HDR/P、现有16sampler边界。不是整图默认逐像素相同声明。
- 原生面板从90→30，实际callback、材质系数、文字/无障碍值一致，仍为中档；未用DOM伪造input事件。
- `r14-clarity-scene.json`实际16/16：固定机位、物理时钟、UTC、波浪、风、C、物质和交互；90→30→0→100→90，五个状态的真实opaque/composed/reflection缓冲有限非负且安全。
- 原始图 `r14-clarity-{90,30,0,100,90_repeat}.png`，离线差异见 `r14-clarity-image-difference.json`。最终回90，并清除QA摄影曝光覆盖。
- `r14-clarity-control-native.png`保存当前真实控制面板；native1209×1292，无临时viewport覆盖。

更浑的水会随路程自然遮住海底，并增加水体散射；没有为看清石子而逆向补亮或减弱水体消光。单次散射仍是现有近似，最浑端不代表复杂多次散射已真实求解。

## 与其他工作分开

R13石子/折射已通过实际原生投掷与单视角像素命中，水冠暗边仍待打磨；局部环境反射候选触发图形中断后已隔离并恢复经实际9/9通过的cac水花。R13近岸wet/dry候选尚未接入主场景，冲滩/回流/泡沫/湿痕和最后性能验收继续。整个长期目标仍未达成。

本页的零新增pass/采样器是源码和实际program检查结论，**没有据暂停读回声称整场锁60fps**。清澈度本身开销很小不意味着全部现有海水/焦散开销很小。
