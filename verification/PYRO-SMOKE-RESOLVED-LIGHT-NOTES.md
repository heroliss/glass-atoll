# Actual-source per-packet lighting candidate

Factory default: disabled. First runtime freeze: field `55a47e8c…`, volume `cd7257e8…`, host `2184a6d4…`. Exact complete baseline sources are in `baselines/smoke-before-resolved-light-field/`. `pyro-smoke-light-field-check.json` is CPU/stub evidence15/15, **not GPU, performance or visual acceptance**. Hardware results belong to the independently authored GPU/Laplace helper and root's actual reports.

The motivating actual-source diagnostic found a spatial colour error:45 of48 root-packet centres had G>R under the120 actual luminous sources, while the old one-cluster proxy was R>G throughout. This candidate changes neither smoke mass nor source intensity to compensate. It replaces only smoke's pyro local slots4/5 with a camera-independent constant RGB SH1 value per physical packet; lamps0–2, torch3/shadow, ambient, directional, front-air treatment, other receivers, clouds and existing GI retain their paths.

The selected approximation is explicit. A packet becomes a **normalized isotropic filter** with variance `trace(Σ)/3`. A luminous emitter becomes a normalized Gaussian with variance `radius²/5`, matching a uniform-volume sphere's second moment, not its exact shape. Their variances add. For source-minus-packet displacement d and `z=|d|/(sqrt(2)σ)`, `F0=Dawson(z)/(σ²z)` and `F1=[erf(z)−2z exp(−z²)/sqrt(pi)] d/|d|³`. The finite coincident-centre limits are F0=1/σ² and F1=0. Coefficients are `C0=Σ rawRGB F0/(4π)` and `C1=3g Σ rawRGB F1/(4π)`, with g=.32. The evaluated field is `C0+dot(C1,worldRayDirection)`; its angular minimum stays nonnegative under the stated model because |F1|≤F0 and3g=.96. Packet mass is already in opacity and is never multiplied into lighting.

The field is not a conditional-ray/full-anisotropic RTE or source-to-smoke shadow solve. Trace preserves only the covariance trace, not the packet's full anisotropy. Per-packet coefficients are spatially constant. SH1 omits higher HG lobes. Nine-node anisotropic mixtures were deliberately rejected because the research prototype exposed large near-source and orientation counterexamples despite preserved moments. This bounded model may yield differently coloured smooth blobs; appearance remains a separate gate.

## API and order

Call `host.prepareLighting({ledger,enabled})` after actual smoke/source updates and **before** choosing storage exposure. The agreed ledger has8 Float32 values/source: `[worldXYZ, emitterVariance, rawRGB, groupIndex]`; emitterVariance is already radius²/5. Published borrowed data is copied to the numerical upload while preparing. Complete at-most-two group metadata feeds `boundSmokeLightField`. Inputs never use photographic C, stored P, view transmission or camera-visible culling.

Preparation returns `{requestedEnabled,enabled,effective,supported,reason,requiredPairs,maxBakePairs,version,reused,…}`. Initial work cap is1,048,576 packet×source pairs, source cap14000, packet cap4096. A valid unsupported workload/hardware configuration explicitly reports effectivefalse and the volume uses its old proxy model; no source rows or unfinished field are silently published. Invalid values, group/layout drift and shader errors throw. The requested UI flag remains a separate caller preference.

The raw group-envelope bound is used before P. During the final smoke draw the raw SH coefficients receive `sceneScale=2^P` exactly once. Shared local uniforms for slots0–3 are already stored and receive no second P. An enabled field excludes the old pyro slots4/5 and fallback two-cluster terms from both its draw and bound. No packet-count multiplier is added to the scattering-source bound.

For isolated QA, `createPyroSmokeLightField` exposes `textures[3]`, `size`, `packedPackets`, `snapshot`, captured `snapshotRevision`, `getRadianceBound`, `diagnostics` and `dispose`. `volume.setResolvedLightingField(field|null)` borrows the exact matching snapshot/layout. Metadata has `host.diagnostics().rendering.resolvedLighting.field`, including bake/version/source/packet counters. A stale snapshot identity or revision refuses the candidate before drawing.

## Resources and numerical scope

Only an enabled candidate allocates the bake quad, numerical inputs and one3-attachment RGBA32F target. Each physical packet occupies one texel/channel `vec4(C0,C1x,C1y,C1z)`. Numerical textures use nearest filtering, no mipmaps and highp samplers. The volume's candidate vertex shader fetches three texels and passes flat coefficients. Its attribute stores the **original snapshot row**, surviving main/mirror depth sorting and culling; it does not use gl_InstanceID as the physical index. The legacy material's shader source is unchanged and is selected again when disabled. Fragment sampling remains independent depth plus existing torch shadow; water's16-sampler path is untouched.

The deterministic special functions use self-generated degree12 Chebyshev fits for Dawson(z)/z on0–2,2–4,4–8, then a positive far asymptotic using variance/d². The offline Float32 fit's sampled maximum relative error is6.27e−7. F1 uses a small-z series below.2, the existing Abramowitz–Stegun erf approximation in the middle and its far limit beyond8. The independent GPU oracle must establish the declared .002 special-function allowance on hardware. Packet variance below1e−30 is outside this bake's stated arithmetic domain; current physical-state minima are larger. `smoke-light-dawson-fit-first.json` retains an offline test's initial factor-of-two error, corrected before runtime coefficients were used; the final fit report passes.

Preparation caches immutable snapshot identity/revision and ledger identity/version/data/count. Same camera/P with the same physical inputs reuses the raw texture. A same-object changed snapshot revision repacks its means/Σ. Disabling removes the contribution immediately, without dropping the cached resources or physical mass. The bake restores logical and physical RT viewport/scissor, framebuffer bindings, target metadata, shadow flags and autoClear; its DPR/actual state behavior still needs the real GPU helper's check.

The15 CPU checks cover default full-source inverse and actual default shader/uniform/attribute/diagnostic parity, lazy allocation, Float32 trace packing independent of mass, invalid SPD/domain refusal, explicit capacity/hardware unsupported states, no stale cap cache after disable, stable sorted/cull indices, selected bound, single P/borrowed uniforms, stale-layout rejection, legacy restore and caller resource ownership. Existing renderer18, air15, local13, finite-phase9, viewport5, host20 and Taylor18 CPU regressions also pass.
