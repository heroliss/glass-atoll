# 新增复杂大型烟花：接入审查

审查范围：只读现有实现；本文件不表示新效果已实现、渲染或验收。行号为新增复杂烟花前的工作区快照，后续插入代码会移动行号。

## 建议落地方式

新增十个**独立类型 ID**，保留原十类的定义、顺序、构造分支和全部已有 effectProfile。优先做“同一主爆、多个根层、不同光色寿命”的新事件构造器；不要把新效果伪装为 `three-heart-v1` 或放宽既有 profile 的固定192根等合同。

适合本次参考的首个效果：2～3层球形星群＋一个世界空间平面核心。所有物理根在主爆时出生；蓝紫内层约2～3秒先熄，球形外层在约4～5秒内平滑经历黄→红→粉→紫→绿，中央图案约6秒最后熄灭。不同层采用不同的初始径向速度、阻力、亮度曲线和尾迹比例。通过曲线控制光色，而不是在渲染帧中按阈值换色或重新随机。

“内层先熄、外层随后、核心最后”应按实际非零发光时段和光学快门尾部验收，不能只比较 `body.life`。极低发射仰角下，较长寿命的核心可能先触地；不能保证所有允许倾角下都完整保留展示顺序。

## 最小数据合同

新的只读 catalog 应包含 ID、中文名、米制主爆升高参考、主爆根数及每层声明。高度、强度未经实物标定时仍明确属于场景作者参考。不要暗示新定义的口径/高度来自已有供应商资料。

构造器建议接收：`definition, eventId, eventSeed, burstTime, burstState, worldBurstFrame, intensityScale, referenceBrightnessGain`；返回以下数据：

- `heads`：唯一非负整数 ID；`birth, life, position, velocity, basePosition, baseVelocity, drag, gravity, kind, radius, intensity, colour`；可选 `burnProfile, emissionReferenceI0, trailProfile, layerId, patternPart`。
- `complexProfile`：新版本元数据，记录层的 ID、根数、可见寿命、速度/阻力硬上界、最长尾迹、最长出生延迟、最大有限推力积分、声明的包围盒合同。与既有 `effectProfile` 命名空间分开。
- `patternFrame`：中央平面图案的固定世界空间 right/up/normal。可以继承发射方位与每发旋转，不能跟随相机做广告牌。
- `events` 第一版维持一次 `launch` 和一次 `burst`，并保留原消费顺序。多次子爆音效/烟源需要额外合同，不能只随意增加事件。
- `endTime` 至少覆盖所有物理根的出生＋寿命、最长光学尾迹及已有烟源最后计划时刻；不要仅按第一层寿命结束事件。

亮度增益必须在构造时只作用一次。若 RGB burnProfile 是权威发光量，应把其各阶段值和 `emissionReferenceI0/intensity` 的归一关系写清，避免头部、尾迹、光照代理与参考亮度再次相乘。

## 烟尘与声音：最容易遗漏的接线

1. `pyro-smoke-events.js:14/24`、`pyro-smoke-trajectory-events.js:29/33`、`pyro-smoke-logical-events.js:8/17`、`pyro-smoke-logical-burn.js:4/35` 都各有原十类允许表。必须一致接纳新类型；否则轻烟能显示，而完整体积烟在首次发射时拒绝。
2. 普通轨迹烟 `parseDescriptor` 规定空中类型恰好1 launch＋1 burst，根寿命须大于`.65`秒，sourceEvents最长16；它只沉积部分代表根，不等于每颗星的连续烟。新复杂类型若走该路径，需如实保留这种近似。
3. 全逻辑烟 `buildLogicalBurnProfile`（约54行）规定 aerial-root 的 `birth===burstTime`，aerial-child 在 `parent.endTime` 出生；`describeFireworkCombustion`（`fireworks.js:74`）也只允许一次空中主爆。新增第二次爆炸事件会打破合同。
4. 根全部同主爆出生，按不同 burnProfile 光色寿命分层，是第一版最兼容的方案。若确实要二次实体壳：采用真实无推力 parent，子根 `birth=parent.birth+parent.life`，保存 `parentBody/parent/velocityDelta`，并按父→子顺序描述；这仍需新的烟源验证。
5. 当前全逻辑物质默认按物理根寿命均匀分配；burnProfile 的 material knots 不会自动变成生产烟源CDF。大段 ignitionDelay 会造成“未发光却已沉积均匀烟”的近似。若要严格晚点火物质时序，需单独扩展物质调度器；本次宜不用长 ignitionDelay。
6. `main.js:1199–1202` 将同一原始事件批交给声音与烟源。`fireworks-audio.js:52` 支持 crackle，但烟源只接受 launch/burst。不要直接给 `event.events` 添加 crackle；需要另一个只供声音消费的次级声事件流，或第一版暂不增加。
7. 主爆录音的混音增益已经验收。新效果可改变位置、持续燃烧结构与发射节奏，保留该音频源及混音参数；`energy` 只是作者参考并被当前音频限制在`.05..2`范围，不能声称按爆炸能量精确测算声压。

## 连续变色、尾迹与有限推进的可行方案

- **首选：解析弹道＋分层RGB曲线。** RGB knots 可设0、.06、.8、1.8、2.7、3.7、4.6、4.9秒等不等间距时间点；所有通道非负，末尾归零。外层绿阶段必须有足够时间与亮度被看到，内层和核心使用自己的时间曲线。变化来自单调时间采样，与FPS无关。
- **空间螺旋造型。** 初始爆炸方向按三维螺旋分布，之后仍受解析阻力和重力。这是持续展开的立体螺旋星群造型，不应称每颗星主动绕圈。
- **小范围主动曲折。** 现有 `createFiniteThrustProfile`/解析响应可以复用，但严格上限为12个力单元、1.06秒、12m/s²、积分12.72m/s。它支持短暂弯钩/蜂群变化，不能据此宣称几十米尺度的完整持续螺旋飞行。
- **较长主动螺旋。** 需另一个明确版本的力合同、解析采样器注册、冲量/位移与快门曲线包围盒，以及独立的物质时序；不能把旧 powered-bees 上限直接放宽。现有 powered 光学短快门限制是1/60秒，新身体若带 thrustProfile，也会触发这一限制。首版可优先稳定交付前两种，再评估新推力版本。
- **尾迹。** 普通 trail profile 最大`.35`秒，既有 radiant版本可到`.88`秒且指定recipe/schema。较长新尾迹应有新版本合同，不冒用旧 radiant ID。清楚区分头部随燃烧时间变色、脱离火星随尾龄变色、以及不发光的物质烟。

## 容量与帧率约束

当前 `fireworks.js:11` opticalRows=262144、ledgerRows=131072，初始14000并按需增长；32发×每发600根×9头尾节点约172800条，仍可能超过物理账本容量。接触切分、推力节点、快门分段还会增大光学行数。应先计算每种新效果的最大根数×尾迹开销，再设每种尾迹/层级预算；不要依赖溢出时截断源。

所有颜色曲线与确定性的造型参数在构造时编译；不要每帧创建数百个 profile。共用不可变模板，加 keyed seed 抖动，保持固定种子的可复现性。两组光照代理仍应合并所有事件能量，完整发光行单独用于渲染/倒影；不应为600颗星创建600盏原生PointLight。

## CPU验收计划

1. **旧值保真**：冻结原十类及所有已有 profiles；多个seed、风历史、强度、角度、快门取样，逐项比较 event/heads 与采样结果；旧数值保持原算术路径。随机类型菜单增长另作明确预期。
2. **新事件完整性**：20类ID唯一，十个新ID手动可构造；层根ID唯一、父子拓扑合法、有限正寿命、所有头/尾/烟源最后时刻被endTime覆盖；全部新增选择可到达。
3. **时间/颜色**：在内层灭灯前后、外层每个颜色过渡、绿色可见期、核心最后熄灭时点检查实际RGB；快门跨越出生和熄灭仍保持积分；不只读菜单文本或life字段。
4. **出生与因果**：主爆前不采样不存在根，延迟根无未来位置；`sampleBody`可返回null必须处理。测试大步、细步和直接跳到同一时刻结果一致，随机抽样不在update/渲染中重做。
5. **空间包围盒**：极端发射倾角−65/0/+65、burst旋转、最大层速度/阻力与有界风；所有实际身体/尾迹/有限推力轨迹处在预测内。解析完整范围另有合同，随机采样仅为独立反例搜索。
6. **烟源**：轻烟、完整体积、全逻辑候选分别测试；类型允许表、事件个数、物质预算、清除/重启、长期保留与有限队列容量不发生无声丢弃。
7. **渲染/听感另验**：CPU通过后由root检查近岛和远景、白天/暮光/夜晚、普通与HDR显示、倒影和声画延迟；限定单枚与少量组合，再决定是否做32发上限压力验收。CPU通过不代表画面或帧率达标。

本审查仅新增此文件，未修改生产代码、未运行浏览器或GPU。

## 实现与验证补充（2026-10-31）

本文件前半部分是构造前审查。后续已按最终约定完成六个所辖生产文件的集成，并保存 `verification/complex-fireworks/before/` 可恢复副本。

- `islandFireworksView(...,{automaticFan:true})` 将观察法线旋转90度，让配置方位上的正负扫射从侧面展开；默认false保留旧手动镜头的全部结果。`frame-check.json` 48/48通过，跨四种画幅、三种焦距、四种方位检查完整包围盒。
- `firework-show-envelope.js` 接入十个新类别的声明式速度、拖曳、寿命、尾迹上限。Helix的火箭有限侧推额外保留120m位置界，并通过解析分段力前缀的相位不变速度模长给后代继承速度留界（目前1.78–2.29m/s），未使用A*T的过宽替代。Vortex的头部有限侧推保留120m位置界。`envelope-check.json` 20/20通过，含旧十类逐字段全等、1,929,225个独立实际轨迹取样反例检查；采样不是解析证明本身。
- 四个烟源适配器均显式接纳新增类别。V扫射96次发射各有唯一时间，独立口部源的总作者参考面积9.6；其余新增空中事件沿用20.35。闪光体和音频专用爆点不增加烟物质。主循环须把 `audioOnly` 记录留给音频，原始物理事件表仍是空中1次发射+1次主爆。
- 新增空中类别的普通轨迹源从实际燃烧图的全部头部和子体中，按 `patternPart` 分层保留12或48条代表路径；每层至少一条，代表人数加权保守分配同一个预算。总核数为24或60，不为每个子体新增整套核。Waterfall的子体能被选中并在已出生后从实际 `sampleBody` 获取位置。未来预留只保存ID、时刻、物质量，没有世界位置或发光属性。
- 完整逻辑候选覆盖每一个实际物质头，Waterfall仅对 `display-waterfall` + `waterfall-ember` + 0.25速度继承 + 父体存活区间内出生开放提前生子；其他类型仍要求父体熄灭时出生。新V扫射严格对应96个lift→comet。
- `smoke-check.json` 30/30通过：旧十类全部适配器的队列记录、诊断和逻辑profile与before逐字段全等；新增十类的因果、总物质、实际子体取样、96扫射时间和12/48代表模式的粗细帧切分一致。发射核记录逐位相同；诊断累计物质量的分组加法仅可能存在约1e-14浮点舍入，以3e-10相对容差检验守恒。最初fixture错误和过严累计值逐位断言保留在 `smoke-check-first.json`。
- 既有 `pyro-smoke-events-check.mjs` 36/36通过，包含旧源30/60/120Hz、长时间留存和身份去重检查。六个文件均通过语法检查。

这些是作者化烟源近似，不是燃料/化学/CFD质量校准。新的V扫射在普通轨迹模式仍以口部烟源为主；完整逻辑候选才沿全部96条运动体持续沉积。完整逻辑模式每枚新增烟花约2,112–5,371个烟核，较普通24/60核的成本大，不能据CPU正确性报告承诺实时帧率。受风、密度合并、发光体着色、反射、镜头构图与GPU性能由主任务继续实景验收。
