# R13 splash optics candidate

Ownership: `splash.js` only. Main/stone/water/locator code is owned by root and is not edited here. This candidate keeps the96 millimetre drops, maximum10cm crown radius and0.34s crown time, gravity9.81 and the common physical clock. It adds no UI circle, emissive term or enlarged particles.

## Established defects and correction

1. Water multiplies its captured environment by `uSkyCubeScale=2^(sceneP-captureP)`. Splash sampled the same cube without that ratio. The candidate aliases the same uniform object; fixed photographic exposure now has consistent raw radiance when storage P changes.
2. Old droplet reflection was weighted by Fresnel in `mix(transmittedSky, reflectedSky,F)` and again by alpha. At normal water incidence F=.02037, the old reflected-cube weight was F×(.055+.7F)=.0014113, versus physical front reflection F=.02037: roughly14.4× suppression. The candidate composites reflected radiance once with alphaF, transmitting the actual background unchanged. It explicitly omits resolved scene refraction/internal caustics rather than inventing a brighter sky transmission.
3. Old crown alpha was an authored `.035+.30F+.06rim`; the candidate uses lossless parallel thin-sheet reflection `R=2F/(1+F)`, `T=(1-F)/(1+F)` with R+T=1, multiplied only by geometric coverage/lifetime fade.
4. The main selective resolve interprets alpha tags as water/foliage. Blended transparent splashes can cross those tags, and old splash wrote reactive0 through the default nonvegetation path. Merely assigning scalar reactive1 proved insufficient: the first actual-GL report had0 reactive pixels despite finite positive crown/drop pixels. Straight-alpha blending multiplies source RGB by source alpha; a scalar MRT output has no explicit alpha. The revised materials use Three's premultiplied-alpha chunk and premultiplied NormalBlending (`ONE, ONE_MINUS_SRC_ALPHA`). This preserves physical RGB compositing and permits scalar reactive1 to survive. The actual premultiplied report records1993 positive reactive pixels, with maximum raw RGB change0.00048828125 from the bb2 straight-alpha candidate. Dedicated opaque/straight/premultiplied/vec4 controls retain their own positive gates.

**Corrected capture contract:** the live sky material contains a solar-disc feature, but both actual environment capture paths deliberately set `uSolarDisk=0` while rendering the cube. After capture they restore the live uniform to1. Inferring cube contents from that restored uniform was an error in the first candidate. The production cube therefore defaults to **disc absent**, and the energy-normalized analytic finite-sun lobe supplies reflected solar radiance. Its angular integral is the shared directional irradiance; screen footprint broadens it without increasing energy. Only explicit `uSkyCubeHasSolarDisk` metadata, or `skyContainsSolarDisc:true`, suppresses this analytic source for a genuinely disc-containing external cube. The current pipeline needs no new flag. Shared pre-exposed `uSkyColor` supplies the no-cube ambient fallback. `r13-splash-before-disc-contract.*` preserves the superseded candidate/report.

## Height/scale limits that remain separate

The CPU `estimateLeafSurface` used by stone collision/drop anchors evaluates an analytic k<9 geometry-filtered sum. The actual GPU water/crown uses baked spectral mip samples plus current interaction ripples and SWE. These are different height queries. This is a real alignment risk, **not yet proven as the cause in a particular invisible actual hit**. The crown already samples the shared GPU `surface()` and follows current water. Airborne drops retain the supplied impact height and ballistic motion. This patch does not make them ride current wave height, because that would change airborne physics.

At distanceD the diameter projects as diameter×projectionY×viewportHeight/(2D). A1mm drop at60m is genuinely subpixel; visibility cannot be guaranteed from every view. That fact does not excuse the optical/history defects above or replace close-view GPU acceptance.
