## What is and is not known

Known: first local fixture rendered no usable active program and reported real material shader/link failures; afterward the live main graphics context was interrupted. Root observed this as the second graphics interruption associated with experimental shader work in this turn (the other was a separate atmosphere candidate).

Unknown: whether this was compiler/resource exhaustion, ANGLE/backend behavior, a GPU-process reset/TDR, another driver mechanism or a combination. The empty compiler logs and subsequent interruption do **not** establish a specific cause. No driver changes, reset, stress test or live retry was performed by this subtask.

## Read-only minimization plan for a separately approved environment

1. Preserve source hashes, browser/GPU-process logs and timing before any new execution. Start with offline GLSL/static validation where available; no live runtime is needed to compare feature size and uniform interfaces.
2. Separate the shader's feature additions: shared wave/SWE functions; shared photographed-sand functions; cloud lookup; directional PCF; bed/Snell/Beer equations. Build one-feature source variants and count static texture sites/uniforms/branches. The12 unique-sampler estimate alone is not a compilation/resource safety guarantee.
3. Any future actual-GL compile experiment belongs in a separate validation environment without the user's active scene. First require a positive trivial four-output MRT draw, then one feature at a time with live/link/compile status and hard external bounds. Do not interpret missing/deleted programs or a lost context as a skipped pass.
4. Prefer a much smaller environment proxy design before reintroducing this composition: e.g. a bounded local bed/sky mean model using existing CPU terrain plus shared average albedo and physical coefficients. Such a simpler model loses texture/shadow detail and must be labeled; it is a design option, not a completed fix. Avoid reusing the entire wave/sand/shadow stack in one splash fragment until separately justified.
5. Preserve default sky-only behavior and the native none/crown/drop controls. Any eventual replacement still needs the same physical phase/camera/source/P/C A/B and actual photo review. The current user-visible crown remains visually unresolved.
