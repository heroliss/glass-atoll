# R12：完整逻辑柳型烟源的成本与提交时刻压缩原型

本轮只写 `verification/r12-smoke-budget-*` 实验文件；运行时 `pyro-smoke-state.js` 保持67fa，FW保持cc864，未更改M、星体覆盖、光强、声音、相机或生产默认。完整原生柳的源带为6291格，默认容量4096，故完整末态需要 **2195** 次合并（先前文字中的2295是减法错误）。

## 先验证原瓶颈，而非一直用16次溢出代表完整柳

[执行器](r12-smoke-budget-check.mjs)、[结果](r12-smoke-budget-check.json) **6/6**。真实native willow/seed42/80°/104°、无风、30Hz逻辑调度，65536仅用于生成所有过去源带；随后按真实throughTime批次流式排入4096状态。不是一次预填全部未来源。每个worker硬上限30秒、内部合并守卫28秒。

两个内存候选分别只改：字符串pair key `i+','+j` 为精确整数 `i*N+j`；再把距离reduce机械展开，保持3次平方、加法顺序。N≤65537时key≤4295098368，远小于2^53，无碰撞。未改候选集合、去重、排序、质量门、M/μ/Σ、热学或其他计算。

六个真实4112格prefix回放顺序A/N/NS/NS/N/A，完整snapshot、diagnostics及全部256个选择项逐位一致。完整6291格的A与NS也全部snapshot/diagnostics/35120项选择顺序逐位一致。

## 大幅减少重复工作的原型：同一提交时刻的局部候选图

[图模块](r12-smoke-budget-graph.js)、[四路执行器](r12-smoke-budget-batch-check.mjs)、[结果](r12-smoke-budget-batch-check.json) **5/5**。这是明确改变压缩时刻的verification-only原型，不是生产兼容补丁。

1. 同一20Hz提交tick内，仍按原生出生时间接收全部真实源，并用原热学、风、扩散将它们推进到tick末。只把容量合并移到该tick末；不会在出生之前物质化，不合并整个cohort为一个packet，不删除M。相对旧模型，最多延后不足.05秒的压缩，显示的已提交物理时钟不变。
2. 在共同时间建立按x/id排序的profile与source邻接图。profile后4邻居、source相邻关系与原候选定义一致；两个heap分别保留同源/其他最小score候选。每次仍选择各前8、执行原完整质量诊断、用原严格quality `<` 和原M/μ/Σ合并。
3. 不变的packet在当前commit内不再演化，因此未改端点的score可复用。合并只改局部x邻居与相连边；节点保留packet相对顺序标签，新节点继承较小标签，等价于原splice之后的i/j字典序。endpoint旧边失效，heap惰性清理且有长度重建门。不是把旧score跨物理时间继续使用。
4. 对照对象是**同样提交时刻合并的朴素batch**。先以12个多source/profile、并列x、变化风、capacity1/4/16的小状态共1068次合并检查，再做完整6291格。

## 下一实施门，不直接上线

- 本原型只用于探索，没有完整生产事务语义。临时packet可超过4096；必须明确限制capacity+staging预算，处理同clock立即输入、partial queue/fault/clear、catchup与输入失败，不能让中间未提交状态被渲染/查询或宣称已维持旧API原子性。
- 先独立审查局部图的边失效、sourceId变null、x并列负mergeID、跨profile、长时风/时钟及heap有界性；验证更多源类型与多峰反例。只要端点/时间变化，旧edge score和诊断缓存都须失效。
- 下一可测精确成本是**当前commit内按edge缓存原mergePair/mergeDiagnostics**：未选中的前8在下一次常常重复，端点没变、时间没变时其质量诊断完全相同；最终选择仍按当前顺序/当前负ID提交。需要缓存ID修正、无alias、失效边和naive全状态复验，不能跨tick复用。
- 开始考虑生产opt-in之前，需有全时序物质/因果/事务、独立有限列误差与实际烟形/受光视频和浏览器帧预算。单柳末态的微小采样τ差，不能成为大幅增加或减少烟量的依据。

建议：保留数字key作为小的精确优化候选，但主线应继续验证共同提交时刻的候选图与诊断缓存，**不是把生产point源永久当作最终方案**。全逻辑源不应因源数多就退回漏掉子星/地面彗星；正确方向是保留完整源、明确压缩误差和实际预算。

## 追加：固定commit内的诊断缓存已完成verification原型

[缓存执行器](r12-smoke-budget-cache-check.mjs)、[实际结果](r12-smoke-budget-cache-check.json) **5/5**。图模块b33文件保持冻结；执行器仅在内存图的返回候选上附加edge引用，并对原`mergeDiagnostics`结果作缓存。每个选中候选的`mergePair`仍按原公式重新计算、使用当前`-(merges+1)`负ID，没有复用早先候选的旧mergeID。端点变化会删除原edge；共同commit结束后整个图销毁，因此没有跨物理时间、热学状态或光学profile复用。

12个小状态的1068次合并依然与naivebatch完全一致。完整原生6291格、4096容量、2195合并的末态snapshot、diagnostics、35120项选择trace和192条有限列结果，也与已完成的naivebatch逐位相同。四路已完成旧结果由明确的同输入/同state/同b33源码hash校验后复用；这次只新增缓存模型实际运行，不把之前旧时序改名为新运行。

本次缓存模型物理回放 **2569.92ms**，compact累计 **1687.42ms**，最大一次advance **58.61ms**；上次未缓存heap为6717.33/4947.64/153.97ms。它们不是同时间片交错AB，不能直接作为稳定FPS倍数。可直接证明的算法工作量是：35120次候选质量调用中 **31410次命中、3710次实际重新计算**，约89.4%的重复诊断消除，而原选择与数值结果保持。源积分、接收/传输、GPU烟体光照/绘制的成本不包含在“消除诊断”中。

最大58.61ms仍有慢帧风险；没有浏览器、长时双发或最终视觉通过。缓存模型与未缓存batch的有限τ/矩误差相同，所以既没有额外增加已测光学差异，也没有把原有采样检查升级成全局误差界。

**特别需要生产设计修复：** 当前实验把`accept`的compact移至tick尾，仅是算法研究。若输入恰好在当前已提交clock、随后`advanceTo`目标不跨tick，实验状态可能暂时保留超容量packet；公开查询也未隔离未提交staging。真实接入必须有明确的原子batch/fence、上限和失败策略，不能直接复制这个变换到生产state并声称API保持。清烟、partial source acceptance/fault、catchup与同clock输入都须独立验收。
