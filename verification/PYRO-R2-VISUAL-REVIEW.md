# R2当前实景：可辨识，仍未达到照片观感

2026-10-27，独立只读评审。实际查看[hero](pyro-r2-smiley-hero.png)、[flare](pyro-r2-smiley-flare.png)、[orbit frame](pyro-r2-orbit-frame.png)原始像素；重新实看Optimum原始[Smiley Shell实拍](https://www.optimum-fireworks.co.uk/images/glossary/smiley_shell.jpg)，并核对其[图鉴说明](https://www.optimum-fireworks.co.uk/glossary.html)。没有改runtime、拍新图或询问用户。

当前120星reference布局比早期dense更好：嘴能辨出离散点，眼不再是完整中空圆环。整体仍像“远处微缩岛屿上方悬着一张发光图案”。GPU数值通过证明功能/边界，不足以消除这层观感。

实拍仅200×131、未知快门/曝光，能支持图案结构和短光迹的相对观察，不能反推精确星数、cd、色谱或展开时间。厂商也明确平面图案可能倾斜或侧看成线，因此不把当前椭圆、规则轮廓或侧视变薄本身判成错误。以下是**当前三处最值得处理的视觉问题**。

## 1. 图案仍有灯牌感；先闭合尺寸/时程，别任意打散星点

**实看：**外圈和口部的亮点仍很接近等尺寸、同一光学语法，脸中间的几团小棕色烟斑与完整轮廓脱节。与实拍中不同长度的短迹/亮芯相比，当前更像固定图形被逐点点亮。但1/120s短快门下出现点状火星可以真实，不能据一张照片就要求每颗有长尾，更不能为了“自然”添加每帧随机抖动。

可证伪的真正缺口是**宽度—时间尚未按产品尺度校准**。截图JSON记录年龄约1.0826s，当前外圈径向初速21m/s、drag=.16。按实际`createFireworkEvent/sampleBody`只读计算同一seed、零共同风的存活外圈：

| 爆后时间 | 可见外圈数 | 实际世界直径 |
| --- | ---: | ---: |
| .6s | 72 | 24.03m |
| 1.0826s（hero阶段） | 72 | 41.75m |
| 1.5s | 72 | 56.01m |
| 2.0s | 72 | 71.89m |
| 2.8s | 72 | 94.79m |
| 3.6s | 37 | 114.94m |

共同线性风/重力平移不改变同drag星的相对直径。当前元数据确实标`widthCalibrated:false`，所以这不是已有测试撒谎；但120m爆高正确，不等于90mm参考产品的完整尺度已正确。[Rise公司官方尺度图](https://rise-hanabi.jp/fireworks/knowledge/)给90mm示例半径30m/高度120m；它是产品参考，不是所有图案弹的普适常数，更没有提供这张实拍的D(t)。后段约115m宽应作为下一阶段校准问题，不能继续把“120m高度已过”当整体真实尺寸验收。

**最小可验证改法：**先不改点数/颜色/源强；固定seed、C、28mm和机位，输出爆后.3/.6/1.1/1.5/2.0/2.8/3.6s及一段连续短片，标实际直径与可见星数。找有时间标尺的同类型实拍，明确“开花宽度”对应哪个阶段，再仅比较一个径向速度候选与原21m/s。若只是点状摄影语法不符，另做能量归一的1/120与1/60s快门对照，不同时改运动、bloom和I。任何新速度都会改变局部重叠与包围，须重新查真实GPU预算。此处**不批准一个任意速度，也不凭静帧宣称速度一定错误**。

## 2. 岛和灯像缩小的舞台；自动全包构图牺牲了场景尺度线索

**实看：**hero中岛的沙滩横向仅约画面五分之一，树冠高度约画面一成以内（目视估计，非分割计量）。大部分是低信息天空/海面，岛本体几乎只剩细黑树丝、两三个无壳体尺度的白亮点和薄沙片；云又呈一排相似的浅色扁块，进一步暴露CG。orbit frame稍有前后关系，但底边只露半截很亮的烟花倒影，容易像意外裁掉的特效层。

这不证明灯的米制尺寸错误。`.065m`半径的灯球在约200–275m距离本来就很小；把它放大或给光池加亮只会制造新的尺度错误。当前28mm/约65.47°竖直视场和全时程包围适合总览，却不自动等于最好的“离岛照片”构图。hero元数据的相机约`[-154.2,12,-118.5]`、target约`[35.8,73.9,22.0]`，主要在照顾高空事件中心，岛被压在远处下缘。

**最小可验证改法：**先做纯pose A/B，保持岛/灯/烟花的真实尺寸、65cd源强、时间、天气、焦距与C不变，记录自动P补偿。可试比当前近10–15%、eye约2–4m的一张照片机位，让沙地照面、树干和灯的位置关系可读；这是试拍起点，**不是已证明不会裁切的生产参数**。用完整展开的几个阶段复核边缘，若不合格就保留总览导演机位，把更近的“环境照片”当独立视角，而非每发反复拉远/拉近。底部倒影应完整进入或明确退出构图，勿以加大反射高光弥补裁切。云形细节仍是独立待改项，pose不能解决它。

## 3. flare亮度不算喧宾夺主，但副像太像复制的整张笑脸

**实看同phase A/B：**flare开启后，真实烟花没有明显被光晕吞没；整体差异较克制，**我不认为当前最优先的问题是“光晕太亮”**。不过下方云附近能辨出一张放大的淡绿/橙副脸，天空上方还有分离的淡色小斑。副像仍保留完整表情轮廓，容易让人识别成整张图案缩放复制，而不是失焦的镜头杂散光。这是当前三仿射核的图像近似，不是能量越界；不能靠“GPU22/22”把镜头像真也验收掉。

**最小可验证改法：**保留默认关闭。若要继续，仅比较ghost输入由t1换成更低通层的候选，或在同一.018总预算内减g、移给更宽veil；不加第二bloom，不给源加I，不提高HDR峰值。固定这张同phase/C/P画面，再增加一个离轴单亮源和一个平场，检查副脸是否仍可辨、黑场是否零、峰值/flux/裁切与成本。低通只是一种有限能量近似，不会把当前算法变成实测镜组追迹。不要为了让开关“看得出区别”把ghost增亮。

## 本轮结论与未出现的功能

当前最该先做的是**尺寸/时程校准与构图**，而不是继续调大光晕或把图案随机做旧。这三张图不能证明已具有分钟级持久烟、烟对光源/星的完整互遮挡、瞬态烟花照云或一跳间接光；根代理正在接线的后续功能不计入本轮已有画面。它们也不能证明连续运动没有闪烁/拖尾、真实HDR显示观感或主观声音通过。

没有给照片级打分，也没有把缺少尚未接通的效果说成回归。建议下轮仍保同机位/同摄影的before与after，让新增烟/照云是否改善氛围与新出现的遮挡/亮度问题能单独判断。
