# R33 水面太阳分支验证草稿

本轮仅完成验证代码与CPU预检。`r33-water-solar-preflight.json` 为 **8/8**；源码准入仍为 `pending:true`，主入口源码值仍为 `PENDING_ROOT_R33_MAIN_EPOCH`。两个导出在读取桥、获取上下文或执行绘制之前都会拒绝调用。没有GPU、浏览器、生产源码或冻结R32文件改动。

唯一私有执行核心只由两个闭合入口调用：

```js
runR33WaterSolarControls(THREE, renderer, { parentLocked: true, bridge })
runR33WaterSolarTiming(THREE, renderer, { parentLocked: true, bridge })
```

桥沿用R32的冻结键和工厂；调用者不能提供尺寸、时刻、uniform、模式或预算。主代理将在HDR问题处理后添加两个固定QA入口、填写最终main epoch并独立审查完整源码/函数指纹，再决定硬件准入。本草稿不自行改变这一状态。

## 三个私有控制

每个控制按基线、候选各绘制一次，共6次。只替换各自私有材质uniform，保留真实网格、相机、时刻、全部采样纹理与实际四MRT回调。

| 控制 | 固定私有值 | 范围 |
|---|---|---|
| 正向太阳键 | 照度1、归一化方向 `[.3,.9,.2]`、颜色 `[1,.97,.90]` | 让原太阳路径实际有正向光源；这是合成回退控制，不能称为真实白天或一致天空 |
| debug15 | 照度0、道具数0、debug15 | 保留aa、未解析斜率和时间方差输出 |
| 道具数1 | 照度0、debug0，首球界 `[1000000,-1000000,1000000,1]` | 依据真实水面世界XZ界≤65536和120m路径上限证明不会命中；只验证计数回退，不验证真实水下道具命中视觉 |

较早方案中“只把照度改为1”仍可能沿用夜晚向下的太阳方向/暗颜色，因此本实现采用后续审查同意的正方向与暖白颜色；不改写R32归档中的原方案文件。每个控制开始都会恢复其私有原始引用和值，防止上一个控制污染下一个。

控制使用原生1209×1292 viewport、固定 `(588,256,32,32)` scissor和单采样RGBA16F/RGBA16F/R16F/R8+depth。6次绘制/renderer调用、14,745,600索引元素、6 clear、0 blit/mip；24次读回、319,488字节，36次有界实际uniform读取。每draw计时≤100ms且健康后才读回或继续；每对四附件严格逐位相同、容差0，失败不换位置、不放宽条件、不继续剩余控制。

## 独立全原生水面计时

控制硬件结果审查通过之后，主代理才决定执行另一个固定调用。顺序为 `warmA → warmB → A1 → B1 → B2 → A2`；只关闭scissor，保留原生尺寸和单采样格式。两程序在查询外预编译；6次绘制、14,745,600索引元素、6 clear、0 blit/mip。只有warmA、warmB和最后A2读取既定ROI，共12次/159,744字节；ABBA中间不插入像素读取。warmB与A2均须与warmA严格逐位一致。

原始六个GPU/CPU提交时间保留，前两次不进入均值，记录A1/A2漂移及两组描述性均值/比值。每组只有两个测量样本；这不证明统计显著性、GPU功耗已稳定、正常8×MSAA整场景提速或FPS。派生的600ms六查询上界不是单帧性能目标。这里只能声称所读ROI相同，不能声称全图逐位一致。

两种工作复用同一35,926,644数值字节的目标，声明计划上界64MiB；程序缓存、对齐与驱动分配不被称为实测显存。没有物理更新、烟花/烟尘求解、反射刷新、镜头或完整场景绘制。
