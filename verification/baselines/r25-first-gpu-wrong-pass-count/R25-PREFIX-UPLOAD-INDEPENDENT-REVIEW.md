## Actual r180 behavior and pitfalls

- `WebGLAttributes.createBuffer` uploads the **full original typed array** with `bufferData`, ignores active update ranges, and leaves those ranges queued. This optimization does not reduce first-use allocation/upload. Later `updateBuffer` uses the queued component offset/count with `bufferSubData`, then clears ranges. No array shrinking/replacement is allowed because r180 rejects changed byte length.
- Zero count returns **before clearing or version incrementing**. This is correct for pending work from an interrupted prior render. A clean zero adds no upload; a previously dirty version can still upload during geometry traversal before `drawInstances(0)` returns. Do not promise zero GL upload solely from `instanceCount=0`.
- Consecutive main/mirror `renderer.render` calls are fresh r180 upload opportunities even within one browser animation callback or with `info.autoReset=false`. `projectObject`/`WebGLObjects.update` occurs before `info.render.frame++`, and the following render uses the incremented frame. Mutating attributes late in `object.onBeforeRender`, after the same-frame geometry traversal, would miss this path; the production fill occurs before render.
- Every geometry attribute is considered by `WebGLGeometries.update`, including a previously created resolved index when the current material does not consume it. A pending unused attribute may upload harmlessly. The next resolved view must still rewrite its active index prefix; field layout remains tied to original records rather than culled/sorted row number.
- If an upload throws, the cached attribute version and pending ranges are not successfully advanced/consumed. A later positive render replaces them with its newly complete prefix. A failure earlier in CPU packing must not be treated as a successful draw; subsequent valid packing rewrites every active value. The prefix change does not introduce partial physical/source publication.
- Transparent `DoubleSide` smoke has `forceSinglePass=false` in this pinned version. One smoke `renderer.render` normally issues **two actual indexed instanced GL draws**. A strict four-actual-draw probe therefore permits two smoke renders, not four A/B renders.

Its scope is CPU control flow and copied storage, not actual renderer/driver/optical acceptance.

## Approved candidate-only first GPU gate

`r25-smoke-prefix-gpu-check.js` exports `runSmokePrefixGPUCheck(THREE, renderer, {parentLocked,createVolume})`. It must run only through root's healthy paused existing-renderer QA lock, after independent review. This agent has not run it.

- One owned volume, maximum capacity eight, three synthetic neutral Gaussian packets. Attach a tiny synthetic resolved field with three DataTextures before the first render; no real lightfield bake or native snapshot.
- First main view draws three instances with original resolved indices `[2,1,0]`, causing expected full-capacity first VBO uploads.
- Second mirror view culls the rear packet, draws two instances and changes indices to `[0,1]`. It must issue one complete active-prefix upload per attribute, including resolved index.
- Intercept `bufferData`/`bufferSubData` only by the owned attributes' exact typed-array identities. Read only the owned small VBOs through `COPY_READ_BUFFER`: 576 bytes per render, below the 4 KB cap. Compare prefix Float32 bits with the CPU arrays and the unused suffix with the first GPU snapshot. No pixel readback or baseline image is part of this gate.
- Count actual instanced GL draws, enforce at most four, and time one interval around each smoke render. Wait for the first interval before permitting the second. First GL/context/shader/FBO/link error, timer disjoint/incomplete result or interval over 25 ms stops the next render. The two faces already queued inside a render cannot be undone.
- Pin both fetched module bytes and the in-memory factory's source. The latter rejects a stale cached factory even if disk bytes are current. Preserve renderer/native READ/DRAW/MRT, physical/current viewport, target metadata, PACK, **all UNPACK/PBO state**, and COPY_READ binding. First DataTexture uploads can change UNPACK; normalization during the probe is bracketed by explicit restoration.
- Instrumentation restores the exact original property descriptors, deleting temporary own properties when methods originally lived on a prototype. Dispose only owned buffers/textures/targets/volume and timer queries.
