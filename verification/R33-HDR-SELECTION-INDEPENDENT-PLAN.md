## Minimal main integration

Have trusted main code copy the closed primitive field set directly from its own Window/Screen after the native fetch resolves, before selection. Do not pass an arbitrary diagnostics/options dictionary as trusted current geometry. Sample again just before applying/publishing if an asynchronous operation intervenes; compare a small geometry signature. Include native report generation/cache age in diagnostics. The existing endpoint can return a5s-cached report, so it is an observation with bounded freshness, not proof of instantaneous topology.

Preserve the explicit device override and numeric manual controls. Do not use an explicit calibration selection as a command to move the page, enable Windows HDR or change system settings. Keep presentation availability/native advanced-color status and calibration provenance distinct. No HDR transfer curve, exposure, paper-white formula or scene radiometry needs to change for this correction.

Current refresh routes are initial startup, focus, dynamic-range media-query change and a30s visible automatic-mode interval. `refreshDisplay` coalesces its fetch but has no QA/benchmark/frozen-workload/quality-application guard. It can presently mutate derived graphics values during a diagnostic. Defer and remember one pending refresh while those locks are active; apply the newest observation after release. Do not silently drop a screen change indefinitely. A cheap visible-only geometry-signature watcher can detect movement because legacy browser APIs have no universally reliable window-move event. It should fetch only after a geometry change, debounce movement, and retain the30s inventory refresh for brightness/hotplug changes. Focus and HDR availability changes remain useful supplemental triggers; foreground changes alone are never a page-screen identity update.

Use a request/revision token across `fetchDisplayHDR`, `hdrOutput.setEnabled` and `displayTransform.configure`, so an older completion cannot publish calibration or labels after a later manual selection/screen move. Re-evaluate latest user options after the fetch; do not restore old options to make a stale request succeed. An ambiguous move must not keep the previous display's native calibration labelled as current. User automatic intent remains automatic.

The existing display signature includes values and friendly-name setting but not the selected native deviceName/confidence. Include actual selected ID and selection basis (or consistently update identity diagnostics even when presentation values are unchanged). Two equal-nit, same-name monitors otherwise look like no change. Refreshes should invalidate only presentation when needed, preserving the existing output-only settled scene history policy.
